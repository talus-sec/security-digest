Scoped Vulnerability Tracking

Database

The most urgent item is the critical SQL injection flaw in MariaDB/MySQL (CVE-2026-44172, CVSS 9.1), which allows unauthenticated attackers to bypass escaping controls and execute arbitrary SQL when using the big5 character set, posing an immediate risk to data confidentiality and integrity.

Formal Vulnerabilities

MySQLCVE-2026-44172CVSS 9.1 · CRITICAL

Summary: MariaDB/MySQL versions 3.3.18 and 3.4.8 fail to properly escape user input when the big5 character set is used with `mysql_real_escape_string()`, enabling SQL injection via the text protocol. An attacker who can send crafted queries to the database server can exploit this without authentication.

Affected Features / Interoperability: The MySQL/MariaDB server’s text protocol handling and escaping logic are impacted; successful exploitation could lead to arbitrary SQL execution, compromising data confidentiality, integrity, and availability, and affecting any application or service that relies on the database.

Source:

  • https://github.com/MariaDB/server/security/advisories/GHSA-pv9p-5w55-55jm
  • https://jira.mariadb.org/browse/CONC-819
  • https://access.redhat.com/errata/RHSA-2026:30135
  • https://access.redhat.com/errata/RHSA-2026:43505
  • https://access.redhat.com/errata/RHSA-2026:47772

Actions:

  • Fix: Upgrade to MariaDB/MySQL 3.3.19 or 3.4.9 (or later).
  • Workaround: Restrict network access to the database server to trusted hosts and disable the big5 character set if not required.
  • Tradeoff: Limiting character set support may break applications that depend on big5 encoding; network restrictions could affect legitimate remote clients.
MySQLCVE-2026-54628CVSS 8.6 · HIGH

Summary: Anyquery versions prior to 0.4.5 expose SQLite virtual table modules (`json_reader`, `log_reader`) through an unauthenticated MySQL‑compatible port, allowing remote attackers to supply arbitrary URLs (including loopback or cloud‑metadata endpoints) and read internal resources.

Affected Features / Interoperability: The Anyquery server’s MySQL‑compatible listener and its virtual table modules are vulnerable; exploitation can lead to SSRF, internal API access, and potential credential leakage, affecting any downstream services that rely on Anyquery for data federation.

Source:

  • https://github.com/julien040/anyquery/commit/27f84fc168310455eaf81ec4ba87eed20298670c
  • https://github.com/julien040/anyquery/releases/tag/0.4.5
  • https://github.com/julien040/anyquery/security/advisories/GHSA-hwrq-8wxh-q4xv
  • https://github.com/julien040/anyquery/security/advisories/GHSA-hwrq-8wxh-q4xv

Actions:

  • Fix: Upgrade Anyquery to version 0.4.5 or later.
  • Workaround: Block external access to the Anyquery MySQL‑compatible port (e.g., firewall rules) and disable the vulnerable virtual table modules if they are not needed.
  • Tradeoff: Disabling the virtual tables may limit functionality for legitimate JSON or log‑file queries; network restrictions could affect authorized users who need remote access.

Summary: Vendure versions before 3.6.5 inadequately sanitize regular‑expression input in the public Shop GraphQL API, permitting unauthenticated attackers to supply catastrophic backtracking patterns that cause denial of service by blocking the Node.js event loop.

Affected Features / Interoperability: The Vendure Shop GraphQL API’s `StringOperators.regex` handling is affected; repeated malicious requests can render the storefront and admin API unavailable, impacting any frontend or integration that depends on Vendure’s GraphQL endpoint.

MySQLCVE-2026-75092CVSS 7.3 · HIGH

Summary: During RHEL 9→10 upgrades, the `leapp-upgrade-el9toel10` scan_mysql actor runs `mysqld --validate-config` as root, allowing a compromised mysql OS user to plant a malicious `mysqld-auto.cnf` and shared object that gets loaded with root privileges when an administrator subsequently runs the Leapp upgrade workflow.

Affected Features / Interoperability: The Leapp upgrade process and MySQL’s persisted configuration (`mysqld-auto.cnf`) are impacted; exploitation could lead to full root compromise on the host during OS upgrades, affecting system integrity and any services running on the upgraded machine.

Source:

  • https://access.redhat.com/errata/RHSA-2026:67608

  • https://github.com/oamg/leapp-repository

Actions:

  • Fix: Apply the updated Leapp packages that address the privilege‑escalation vector (refer to Red Hat errata RHSA‑2026:67608/67609).
  • Workaround: Ensure the mysql OS account is hardened (e.g., restrict login, use least‑privilege containers) and audit `/var/lib/mysql` for unauthorized `mysqld-auto.cnf` or shared objects before running Leapp upgrades.
  • Tradeoff: Hardening the mysql account may limit legitimate administrative tasks; pre‑upgrade auditing adds operational overhead but does not degrade functionality.

The most urgent item this cycle is CVE-2026-85596 (Traefik Kubernetes Ingress NGINX provider, CVSS 9.8 CRITICAL), an authentication bypass that causes Traefik to fall back to the entry point's default TLS configuration — which does not request a client certificate — when two Ingress objects share the same host, CA secret, and client-authentication mode. In a healthcare environment running mTLS-based service mesh or ingress, this is the highest-priority remediation target.

KubernetesCVE-2026-85596CVSS 9.8 · CRITICALActively exploited · CISA KEV

Summary: Traefik versions >= v3.7.0 and <= v3.7.10 contain an authentication bypass in the Kubernetes Ingress NGINX provider. The TLS option generated for an Ingress carrying the `nginx.ingress.kubernetes.io/auth-tls-secret` annotation was named after the Ingress namespace and name. Two Ingress objects sharing the same host, the same client CA secret, and the same client-authentication mode produced two distinct TLS option names for that host. Traefik treats this as a TLS options conflict and falls back to the entry point's default TLS configuration, which does not request a client certificate, so a route configured with `nginx.ingress.kubernetes.io/auth-tls-verify-client: "on"` becomes reachable without a client certificate. Only the v3.7 line is affected; fixed in v3.7.11.

Affected Features / Interoperability: Traefik v3.7.x Kubernetes Ingress NGINX provider TLS option generation and client certificate authentication. Downstream impacts include complete bypass of mTLS client-certificate verification on affected routes, allowing unauthenticated access to services that require client certificates. This is particularly critical for healthcare environments relying on mTLS for service-to-service or external-to-internal authentication. Database drivers and extensions are not directly mentioned.

Source:
