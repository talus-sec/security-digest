Scoped Vulnerability Tracking

Database

The most urgent threat is CVE-2026-59971 in MySQL, a Critical (10.0) vulnerability in the MCP Server that allows unauthenticated network attackers to execute arbitrary SQL commands and modify database objects directly. This flaw is actively exploited in production environments and grants full database control without any authentication barrier, making it the highest priority remediation for the healthcare database fleet.

Formal Vulnerabilities

MySQLCVE-2026-59971CVSS 10.0Actively exploited · CISA KEV

Summary: The MySQL MCP Server (version <0.4.2) constructs insecure SSE transports that lack authentication and DNS rebinding protection, exposing endpoints that allow unauthenticated clients to execute arbitrary `execute_sql` commands and modify database objects. An attacker can directly manipulate the configured database, read or write files, and even achieve code execution if FILE privileges exist. The vulnerability is fixed in version 0.4.2.

Affected Features / Interoperability: The MCP Server interface (`/`, `/sse`, `/messages`) lacks authentication on all routes and binds to `0.0.0.0`, enabling network-wide access to the underlying MySQL instance. Replication streams and client drivers are directly compromised through these endpoints.

Source: https://github.com/designcomputer/mysql_mcp_server/commit/a96549f4a4d65443fd6e9c7f2324fba9a5c80a82 https://github.com/designcomputer/mysql_mcp_server/issues/92 https://github.com/designcomputer/mysql_mcp_server/releases/tag/v0.4.2 https://github.com/designcomputer/mysql_mcp_server/security/advisories/GHSA-rqfv-2mw9-78g2

Actions:

  • Fix: Upgrade MySQL MCP Server to version 0.4.2 or later immediately.
  • Workaround: Restrict MCP Server ports to internal networks only and disable SSE transport until patched.
  • Tradeoff: None—immediate patching is required; delaying exposure risks full database compromise.
MySQLCVE-2026-50006CVSS 9.1

Summary: The Anyquery SQL query engine (pre-0.4.5) sends unauthenticated MySQL traffic to an SQLite backend without proper attachment targeting, allowing remote attackers to write arbitrary files to the server filesystem and achieve RCE when combined with privileged processes.

Affected Features / Interoperability: Anyquery’s MySQL-compatible server port (v0.4.5+) exposes unattached SQLite virtual tables (`json_reader`, `log_reader`) to unauthenticated clients, enabling file system read/write and potential command execution.

Source: https://github.com/julien040/anyquery/commit/27f84fc168310455eaf81ec4ba87eed20298670c https://github.com/julien040/anyquery/releases/tag/0.4.5 https://github.com/julien040/anyquery/security/advisories/GHSA-xrcf-6jh3-ggvx

Actions:

  • Fix: Upgrade Anyquery to version 0.4.5 or later.
  • Workaround: Disable the MySQL-compatible server port and restrict Anyquery to read-only connections only.
  • Tradeoff: No significant degradation; temporary removal of the vulnerable feature class.
