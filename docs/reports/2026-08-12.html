Daily Database Security Digest

Executive Summary

The most urgent vulnerability is CVE-2026-49261 in MariaDB/MySQL, rated CRITICAL (CVSS 10.0), which allows unauthenticated remote attackers to execute arbitrary shell commands on database nodes via the `wsrep_notify_cmd` feature. MySQL

PART A -- Formal Vulnerabilities

#### CVE-2026-49261 (CVSS 10.0 CRITICAL)

Summary: A critical vulnerability in MariaDB server (a MySQL fork) allows unauthenticated attackers to execute arbitrary shell commands on database nodes when `wsrep_notify_cmd` is enabled. The vulnerability is triggered by crafting a malicious joiner node name containing shell commands, which are executed on the receiving node.

Affected Features / App Interoperability: The `wsrep_notify_cmd` feature in MariaDB replication. This impacts Galera cluster deployments and any application relying on multi-node MySQL/MariaDB replication.

Source:

  • https://github.com/MariaDB/server/security/advisories/GHSA-3p3m-4x7c-p4pw
  • https://jira.mariadb.org/browse/MDEV-39721

Actions:

  • Fix: Upgrade to MariaDB versions 10.6.27, 10.11.18, 11.4.12, 11.8.8, or 12.3.2.
  • Workaround: Disable `wsrep_notify_cmd` if immediate patching is not possible.
  • Tradeoff: Disabling `wsrep_notify_cmd` may break custom cluster notification scripts or integrations relying on this feature.

#### CVE-2026-72869 (CVSS 9.9 CRITICAL)

Summary: A critical vulnerability in Dokploy (a PaaS tool) allows authenticated users with backup:restore permissions to inject arbitrary shell commands via the `databaseName` parameter during database restoration. This affects PostgreSQL, MariaDB, MySQL, and MongoDB backups.

Affected Features / App Interoperability: The `backup.restoreBackupWithLogs` tRPC subscription in Dokploy. This impacts environments using Dokploy for database management and automation.

Source:

  • https://github.com/Dokploy/dokploy/security/advisories/GHSA-f7mp-9jfp-mjrr

Actions:

  • Fix: Upgrade to Dokploy version 0.29.13.
  • Workaround: Restrict backup:restore permissions to trusted users only.
  • Tradeoff: No significant tradeoff if permissions are properly managed.

#### CVE-2026-18617 (CVSS 8.8 HIGH)

Summary: A high-severity vulnerability in the Data Science Pipelines Operator (DSPO) allows namespace editors to inject dangerous parameters into MySQL DSN strings, enabling `LOCAL INFILE` functionality and potential privilege escalation to cluster-admin.

Affected Features / App Interoperability: The `spec.database.customExtraParams` field in DSPO. This impacts Kubernetes-based data science workflows using MySQL as a data source.

Source:

  • https://access.redhat.com/errata/RHSA-2026:53261

Actions:

  • Fix: Apply Red Hat patches (RHSA-2026:53261, RHSA-2026:53262, RHSA-2026:53263).
  • Workaround: Validate and sanitize `customExtraParams` inputs.
  • Tradeoff: Input validation may complicate legitimate use cases.

#### CVE-2026-48774 (CVSS 7.5 HIGH)

Summary: A ProxySQL vulnerability allows bypassing read-only restrictions in the GenAI/MCP `run_sql_readonly` tool by chaining read-only and write statements (e.g., `SELECT 1; RENAME TABLE ...`).

Affected Features / App Interoperability: ProxySQL's GenAI/MCP tool for MySQL targets. This impacts applications using ProxySQL as a MySQL proxy with GenAI integrations.

Source:

  • https://github.com/sysown/proxysql/security/advisories/GHSA-7wh6-2vcc-gcm4

Actions:

  • Fix: Upgrade to ProxySQL version 3.0.9.
  • Workaround: Disable MCP unless required; restrict network exposure; use read-only database credentials.
  • Tradeoff: Disabling MCP may break GenAI integrations.
