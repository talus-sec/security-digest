Scoped Vulnerability Tracking

Database

The single most urgent item this week is CVE-2024-58385 affecting Microsoft SQL Server (via the Yonyou U8 CRM platform), which presents a critical CVSS of 9.8. This vulnerability is an unauthenticated, remote SQL injection that allows arbitrary operating system command execution on underlying database hosts when `xp_cmdshell` is active, with active exploitation observed in the wild by the Shadowserver Foundation. For PostgreSQL environments, particularly homelabs and enterprise partition management, CVE-2026-61820 (pg_partman, CVSS 8.5) is highly critical, allowing a low-privileged user to escalate to database-wide superuser compromise and OS command execution via crafted column names. Additionally, organizations routing traffic through Warpgate bastion hosts must urgently patch multiple high-severity vulnerabilities, including session recording eavesdropping (CVE-2026-63330, CVSS 7.7) and stored cross-site scripting (CVE-2026-58491, CVSS 9.3), which expose proxied MySQL, PostgreSQL, and SSH credentials.

---

Formal Vulnerabilities

Skip systems with no entries? No, all four systems have formal vulnerability entries. Presenting them sorted as provided in the dataset.

MySQLCVE-2026-58491CVSS 9.3 · CRITICAL

Summary: This is a stored cross-site scripting (XSS) and open redirect vulnerability in the Warpgate bastion host's SSO provider endpoints. An attacker can craft a malicious `next` parameter that, when a victim authenticated user completes the SSO flow, executes arbitrary JavaScript in the victim's browser within the Warpgate origin, stealing session data and allowing administrative actions. This issue is fixed in version 0.25.5.

Affected Features / Interoperability: Affects the SSO provider API endpoints (`/@warpgate/api/sso/providers/:name/start` and `/@warpgate/api/sso/return`) in `warpgate-protocol-http/src/api/sso_provider_list.rs`. Downstream, this compromises the security of any SSH, HTTPS, or MySQL session routed through a Warpgate bastion, potentially leading to full account takeover.

Source:

  • https://github.com/warp-tech/warpgate/commit/eab0548f018d95b5f96f8e913527000e05ed93a2
  • https://github.com/warp-tech/warpgate/releases/tag/v0.25.5
  • https://github.com/warp-tech/warpgate/security/advisories/GHSA-3c3w-75j2-7h74

Actions:

  • Fix: Upgrade Warpgate to version 0.25.5 or later.
  • Workaround: Restrict access to SSO configuration for trusted administrators only and enforce strict Content-Security-Policy (CSP) headers.
  • Tradeoff: Minimal tradeoff if SSO is not heavily utilized; otherwise, it degrades automated single sign-on functionality until patched.
MySQLCVE-2026-63330CVSS 7.7 · HIGH

Summary: A missing authorization check in the Warpgate admin API allows any authenticated regular user to subscribe to active session recordings via the WebSocket stream endpoint. By identifying active recording UUIDs, an attacker can stream real-time terminal input and output of proxied SSH, MySQL, or PostgreSQL sessions, leaking sensitive credentials and commands. This issue is fixed in version 0.25.6.

Affected Features / Interoperability: Impacts the `api_get_recording_stream` function in `warpgate-admin/src/api/recordings_detail.rs` and the `/@warpgate/admin/api/recordings/{uuid}/stream` endpoint. Downstream, this breaks the confidentiality of all audit logs and proxied database/SSH sessions managed by the bastion.

Source:

  • https://github.com/warp-tech/warpgate/commit/f5cb06ea09065f375870ccee64fe721a2ca79766
  • https://github.com/warp-tech/warpgate/releases/tag/v0.25.6
  • https://github.com/warp-tech/warpgate/security/advisories/GHSA-2q37-6vxr-26jr

Actions:

  • Fix: Upgrade Warpgate to version 0.25.6 or later.
  • Workaround: Implement reverse proxy rules or network-level access controls that block non-administrative users from accessing the admin API recording endpoints.
  • Tradeoff: Prevents non-administrative audit reviewers from legitimately monitoring stream details if their workflow relies on the web UI.
MySQLCVE-2026-90997CVSS 7.4 · HIGH

Summary: A row-count semantic mismatch between the database driver and Keycloak's application logic in stateless mode allows attackers to bypass replay protection mechanisms. An attacker who intercepts single-use security artifacts (such as JWT assertions or TOTP codes) can replay them to gain unauthorized access to the token endpoint or login flows.

Affected Features / Interoperability: Impacts Keycloak deployments configured in stateless mode utilizing MySQL or MariaDB databases. Downstream, this compromises the entire identity and access management (IAM) infrastructure, potentially leading to account takeover of services relying on Keycloak for authentication.

Source:

  • https://access.redhat.com/security/cve/cve-2026-90997
  • https://github.com/keycloak/keycloak

Actions:

  • Fix: Upgrade Keycloak to a patched release that resolves the row-count mismatch in stateless mode (consult vendor release notes).
  • Workaround: Transition Keycloak deployments to stateful mode when backed by MySQL/MariaDB, or enforce strict token binding.
  • Tradeoff: Stateful mode introduces scalability and performance overhead due to session state replication.
MySQLCVE-2026-94042CVSS 6.3 · MEDIUM

Summary: An unauthenticated SQL injection vulnerability exists in the `admin/add_table.php` file of the AdithyaYelloju Restaurant Management System. The `table/members/price` argument is manipulated to inject arbitrary SQL queries directly into `mysqli_query` calls, allowing remote database compromise

Cloud Security

The most urgent item in today's cloud security digest is CVE-2026-61682 in Kubernetes, a CISA KEV-confirmed vulnerability with a CVSS score of 9.9 (CRITICAL). This flaw allows authenticated tenants to impersonate cluster administrators and bypass authorization controls, enabling cross-workspace resource manipulation, secret theft, and RBAC data exfiltration. Immediate patching to versions 0.31.4 or 0.32.2 is required. Other critical issues include a Google Cloud Gemini SDK RCE vulnerability (CVE-2026-19407) and a Docker Mailu authentication bypass (CVE-2026-85751), both requiring urgent remediation.

Formal Vulnerabilities

KubernetesCVE-2026-61682CVSS 9.9 · CRITICALActively exploited · CISA KEV

Summary: The kcp front-proxy fails to sanitize identity headers (X-Remote-User, X-Remote-Group, etc.) before forwarding requests to shards. Authenticated tenants can inject administrative group memberships (e.g., system:masters) to impersonate cluster admins, bypass authorization, and access/modify resources across workspaces. Exploitation requires authenticated access to the kcp control plane.

Affected Features / Interoperability: kcp control plane proxy, shard authentication, Kubernetes RBAC enforcement, workspace isolation. Impacts multi-tenant Kubernetes deployments using kcp for form-factor abstraction.

Source: https://github.com/kcp-dev/kcp/commit/7437cdcfec8f927d1a9bf1b2dd1e075d038e27ca

Actions:

  • Fix: Upgrade to kcp versions 0.31.4 or 0.32.2.
  • Workaround: Disable kcp front-proxy until patching; restrict tenant access to control plane APIs.
  • Tradeoff: Temporary loss of multi-tenant isolation capabilities.

Affected Features / Interoperability: OpenShift Observability Operator, ServiceAccount creation, ClusterRole bindings, namespace-scoped custom resources.

Source: https://access.redhat.com/security/cve/CVE-2025-2843
