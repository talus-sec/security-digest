Scoped Vulnerability Tracking

Database

The most urgent item is CVE-2026-59971 (CVSS 10.0 CRITICAL) in the MySQL MCP Server: an unauthenticated, network-reachable flaw that allows arbitrary SQL execution and potential code execution via DNS rebinding when the SSE transport is enabled, affecting any deployment using the Model Context Protocol server with non-default transport settings. No CISA KEV entries appear in this dataset, so the highest-CVSS vulnerability takes precedence. Microsoft SQL Server CVE-2023-54400 (CVSS 9.8) and multiple MongoDB driver flaws (CVSS 8.3) also warrant immediate attention.

Formal Vulnerabilities

MySQLCVE-2026-59971CVSS 10.0 · CRITICAL

Summary: The MySQL MCP Server (Model Context Protocol server) prior to version 0.4.2, when configured with `MCP_TRANSPORT=sse`, binds an unauthenticated HTTP/SSE endpoint to `0.0.0.0` without DNS rebinding protection. A remote attacker can directly call the `execute_sql` tool or use DNS rebinding to force a victim's browser to relay same-origin requests, achieving unauthenticated SQL execution. If the MySQL account has `FILE` privileges, this extends to arbitrary file read/write and potential code execution. The default `stdio` transport is not affected.

Affected Features / Interoperability: The SSE transport mode of the MySQL MCP Server (`src/mysql_mcp_server/server.py`). Downstream impact includes any AI agent or client using the MCP server to interact with MySQL databases; replication, client drivers, and extensions are not directly affected unless they route through this MCP server.

Source: https://github.com/designcomputer/mysql_mcp_server/commit/a96549f4a4d65443fd6e9c7f2324fba9a5c80a82, https://github.com/designcomputer/mysql_mcp_server/issues/92, https://github.com/designcomputer/mysql_mcp_server/releases/tag/v0.4.2, https://github.com/designcomputer/mysql_mcp_server/security/advisories/GHSA-rqfv-2mw9-78g2

Actions:

  • Fix: Upgrade to MySQL MCP Server 0.4.2 or later.
  • Workaround: Do not use `MCP_TRANSPORT=sse`; stick to the default `stdio` transport. If SSE is required, place the service behind an authenticated reverse proxy and restrict network exposure.
  • Tradeoff: Disabling SSE transport removes HTTP-based MCP access, which may break integrations expecting HTTP/SSE endpoints. Reverse proxy adds operational complexity.

Affected Features / Interoperability: PostgreSQL Anonymizer extension `anon.hash()` function. Downstream: anonymized data security; salt recovery undermines masking guarantees.

Source: https://gitlab.com/dalibo/postgresql_anonymizer/-/issues/685

Actions:

  • Fix: Upgrade PostgreSQL Anonymizer to 3.2.3 or later.
  • Workaround: Restrict `EXECUTE` on `anon.hash()` to trusted roles; avoid using sub-selects with masked roles.
  • Tradeoff: Restricting function access may break legitimate anonymization workflows.
