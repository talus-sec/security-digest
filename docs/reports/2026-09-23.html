Scoped Vulnerability Tracking

Database

Today's Database digest highlights Warpgate's critical SSO endpoint vulnerability (CVE-2026-58491, CVSS 9.3) as the most urgent item due to its combination of stored XSS, open redirect, and admin API exposure in a bastion host that sits in front of MySQL; no CISA KEV-confirmed entries are present in the current formal feed, so all items remain theoretical severity. PostgreSQL's pg_partman privilege escalation (CVE-2026-61820, 8.5) and Spring Statemachine deserialization RCE affecting MongoDB backends (CVE-2026-41862, 8.8) follow as high-severity findings. Healthcare infrastructure owners should prioritize Warpgate and pg_partman patches, while homelab operators running Postgres/Vault/mTLS should verify pg_partman usage and review Keycloak replay protections.

Cloud Security

One-paragraph executive summary, highlighting the single most urgent item (a CISA KEV-confirmed entry always outranks a merely high-CVSS entry, since it's confirmed exploitation vs. theoretical severity).

The most urgent cloud security issue this week is CVE‑2026‑92574, a flaw in CRI‑O’s checkpoint restore that lets a privileged user bypass the destination security context and run with elevated privileges; its CVSS score of 8.8 makes it the highest‑severity vulnerability in the current data set.

Formal Vulnerabilities

KubernetesCVE-2026-92574CVSS 8.8 · HIGH

Summary: A flaw in CRI‑O’s checkpoint restore allows a user who can create a pod from a malicious checkpoint to bypass the destination security context, retaining credentials and capabilities, which can lead to privilege escalation across container boundaries. Exploitation requires the ability to create a pod from a malicious checkpoint image and have checkpoint restore enabled.

Affected Features / Interoperability: CRI‑O checkpoint restore functionality; can break pod security and enable cluster‑wide privilege escalation.

Source: https://access.redhat.com/security/cve/CVE-2026-92574, https://bugzilla.redhat.com/show_bug.cgi?id=2535436

Actions:

  • Fix: Upgrade to the patched CRI‑O version (not yet released); monitor Red Hat/OPA releases for the upcoming fix.
  • Workaround: Disable checkpoint restore on affected nodes or restrict pod creation to trusted images via admission control.
  • Tradeoff: Disabling checkpoint restore may reduce operational flexibility for rolling updates, but no significant security tradeoff if the feature is not required.
KubernetesCVE-2026-61672CVSS 7.1 · HIGH

Summary: Capsule’s forbidden list sorting logic incorrectly handles case‑insensitive keys, allowing a tenant owner to bypass namespace and metadata restrictions. An authenticated tenant can craft a list with mixed‑case keys to evade the policy check.

Affected Features / Interoperability: Capsule multi‑tenancy policy enforcement; can affect namespace creation, network policies, and scheduling.

Source: https://github.com/projectcapsule/capsule/commit/755cef54bf4a1bc56d6692130132bc70755bef46, https://github.com/projectcapsule/capsule/pull/1982, https://github.com/projectcapsule/capsule/releases/tag/v0.13.7, https://github.com/projectcapsule/capsule/security/advisories/GHSA-gjw4-3v3v-rqxg

Actions:

  • Fix: Upgrade to Capsule version 0.13.7 which corrects the sorting logic.
  • Workaround: Ensure forbidden lists use uniformly lowercase keys or avoid mixing case to prevent the false negative.
  • Tradeoff: Re‑formatting existing lists may be required, but otherwise no functional impact.

Affected Features / Interoperability: Capsule Tenant management; can prevent namespace creation or updates for affected tenants.

Source: https://github.com/projectcapsule/capsule/commit/8d89d6865df6f41c7faa22fc9e807a57b01bfd0e, https://github.com/projectcapsule/capsule/pull/1983, https://github.com/projectcapsule/capsule/releases/tag/v0.13.7, https://github.com/projectcapsule/capsule/security/advisories/GHSA-gxjc-74v5-3vx3
