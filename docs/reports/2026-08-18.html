Cloud Security

The most urgent item is CVE-2026-73842 in OpenChoreo, a Kubernetes-native developer platform, which exposes critical internal APIs without authentication, allowing unauthenticated remote attackers to read secrets, mutate workloads, and execute commands across connected clusters. This is compounded by active exploitation reports and a CVSS score of 9.0 (Critical).

Formal Vulnerabilities

KubernetesCVE-2026-73842CVSS 9.0 · CRITICALActively exploited · CISA KEV

Summary: A race condition in the OpenChoreo Kubernetes platform exposes internal APIs (`/api/proxy/`, `/api/exec/`, `/api/wirelogs/`) without requiring client certificates or tokens, enabling unauthenticated network-reachable attackers to read tenant Kubernetes Secrets, mutate workloads, and execute commands across connected data planes. No authentication is required, and the vulnerability is exploitable over the network.

Affected Features / Interoperability: Impacts OpenChoreo versions prior to 1.0.3, 1.1.3, and 1.2.0-rc.2. Affects internal cluster gateway services and any connected data planes relying on OpenChoreo for workload management. Downstream impacts include unauthorized access to Kubernetes Secrets, potential compromise of managed clusters, and lateral movement within Kubernetes environments.

Source:

  • https://github.com/openchoreo/openchoreo/commit/50fcae3f1753fd0ac3ae655a3fc080a761c49c04
  • https://github.com/openchoreo/openchoreo/commit/93e6f10953cfc249af2222ddb6730d4b0a729129
  • https://github.com/openchoreo/openchoreo/commit/e3da3c63dcf0895c693cb17ce142ef95e959b62a
  • https://github.com/openchoreo/openchoreo/pull/4256
  • https://github.com/openchoreo/openchoreo/pull/4258

Actions:

  • Fix: Upgrade to OpenChoreo versions 1.0.3, 1.1.3, or 1.2.0-rc.2.
  • Workaround: Restrict network access to internal listeners exposing the vulnerable endpoints.
  • Tradeoff: Network restrictions may limit legitimate internal communication between components.
