Scoped Vulnerability Tracking

Database

Executive Summary

The highest-severity item in this feed is CVE-2026-104457 (CVSS 8.6 HIGH) in YesWiki, an unauthenticated SQL injection in the Bazar filtertags action that can leak arbitrary table data including password hashes on default installs. Important context for DB admins: the majority of the MySQL-grouped entries below are vulnerabilities in applications connecting to MySQL (YesWiki, appointment booking, LMS, drug recommendation systems), not vulnerabilities in the MySQL database engine itself; no MySQL server binary patch is required for these. In a healthcare environment, the patient-facing applications (appointment booking, drug recommendation) are the highest risk due to potential PHI exposure via SQLi. No entries in the provided feed are marked as CISA KEV-confirmed, so ranking is based on CVSS severity and exploit availability.

Formal Vulnerabilities

MySQLCVE-2026-104457CVSS 8.6 · HIGH

Summary: YesWiki before 4.6.7 contains an SQL injection in the Bazar filtertags action, which wraps unescaped `filterN` attribute tokens in quotes and concatenates them into a raw `tags.value IN (...)` clause. Unauthenticated attackers on default installs can save filtertags markup with a trailing-backslash token to break quote parity under MySQL backslash escaping, enabling a five-column UNION subquery to read arbitrary table data such as password hashes.

Affected Features / Interoperability: YesWiki Bazar filtertags action / page markup parsing. Downstream impact includes credential theft (password hashes) and arbitrary data read from the connected MySQL database; does not affect the MySQL server binary or replication.

Source:

  • https://github.com/YesWiki/yeswiki/security/advisories/GHSA-p87r-f4x4-8r4g
  • https://www.vulncheck.com/advisories/yeswiki-before-4.6.7-sql-injection-via-filtertags-filtern-parameter

Actions:

  • Fix: Upgrade YesWiki to version 4.6.7 or later.
  • Workaround: Disable the Bazar filtertags action or restrict page-editing privileges to authenticated administrators until patched.
  • Tradeoff: Disabling filtertags degrades page tagging/filtering functionality for end users.

MySQL — CVE-2026-43917 (CVSS UNSCORED severity not provided)

Summary: Dokploy (0.19.0 and earlier) is a self-hostable PaaS where the `protectedProcedure` middleware verifies authentication but does NOT enforce organization scoping. Each endpoint must individually verify the resource's org matches the session's `activeOrganizationId`. Affected endpoints include deployment, rollback, backup, volume-backup, cluster, and mount operations across Postgres, MariaDB, MySQL, Mongo, and Compose services.

Affected Features / Interoperability: Dokploy organization scoping / multi-tenancy. Downstream impact includes cross-organization data access and resource manipulation (e.g., backups, deployments, cluster nodes) for any authenticated user; relevant if Dokploy is used to host the homelab or production DB instances.

Source:

  • https://github.com/Dokploy/dokploy/security/advisories/GHSA-f8wj-5c4w-frhg

Actions:

  • Fix: Upgrade Dokploy to a version later than 0.19.0.
  • Workaround: Manually verify org scoping logic in the affected endpoints (`deployment.ts`, `backup.ts`, `cluster.ts`, etc.) if upgrading is not immediately possible.
  • Tradeoff: Manual verification of org scoping is error-prone and adds operational overhead.
MongoDBCVE-2026-81521CVSS 6.5 · MEDIUM

Summary: The MongoDB Go Driver's client-level bulk write operation may accept a caller-supplied database name containing a reserved separator character without escaping it before building the target namespace. An application passing untrusted input as a database name could have the write directed at an unintended database and collection. Only the `Client.BulkWrite` API is affected.

Affected Features / Interoperability: MongoDB Go Driver (`go.mongodb.org/mongo-driver/v2`) `Client.BulkWrite` API. Downstream impact includes writes to unintended databases/collections, potentially corrupting data or leaking data across tenants; relevant to Go-based cloud services and homelab tooling.

Source:

  • https://jira.mongodb.org/browse/GODRIVER-4075
  • https://pkg.go.dev/go.mongodb.org/mongo-driver/v2@v2.8.2

Actions:

  • Fix: Upgrade the MongoDB Go Driver to v2.8.2 or later.
  • Workaround: Validate and sanitize database names client-side before passing them to `Client.BulkWrite`.
  • Tradeoff: Client-side validation adds complexity and must be maintained across all code paths using bulk writes.

MongoDB — CVE-2026-106119 (CVSS UNSCORED severity not provided)

Summary: LangChain prior to 1.3.1 does not enforce the documented string type for an untrusted structured session identifier in `MongoDBChatMessageHistory`, allowing the identifier to be interpreted as a MongoDB query condition rather than a literal value. An attacker able to invoke chat-history operations can read, modify, or delete another user's stored conversation in a shared MongoDB collection. Fixed in version 1.3.1.

Affected Features / Interoperability: LangChain `MongoDBChatMessageHistory` component. Downstream impact includes cross-user conversation leakage or tampering in LLM applications sharing a MongoDB collection; does not affect the MongoDB server binary.

Source:

  • https://github.com/langchain-ai/langchainjs/commit/946e3d856ff1f8ce7f7b9374c83f680a6ada79af
  • https://github.com/langchain-ai/langchainjs/pull/11672
  • https://github.com/langchain-ai/langchainjs/releases/tag/@langchain/mongodb@1.3.1
  • https://github.com/langchain-ai/langchainjs/security/advisories/GHSA-m6rx-h84q-8r95

Actions:

  • Fix: Upgrade LangChain to version 1.3.1 or later.

Summary: External Secrets Operator versions 0.10.0 through 1.3.1 have a webhook generator initialization bug that clears the label-enforcement flag after it is set, allowing secrets without the required `external-secrets.io/type=webhook` label to be created.

Affected Features / Interoperability: The External Secrets Operator webhook generator is impacted; this could bypass label enforcement policies and lead to unintended secret exposure.

Source: https://github.com/external-secrets/external-secrets/commit/25aa09275861e3ed6fc5d2a1a60b9ac3df4a93ba, https://github.com/external-secrets/external-secrets/pull/5901, https://github.com/external-secrets/external-secrets/releases/tag/v1.3.2, https://github.com/external-secrets/external-secrets/security/advisories/GHSA-q7hv-xx6h-q2x8

Actions:

  • Fix: Upgrade to External Secrets Operator version 1.3.2 or later.
  • Workaround: Enforce label requirements via alternative admission controllers or policy engines and avoid using the webhook generator until patched.
  • Tradeoff: May lose webhook-based secret automation capabilities.
KubernetesCVE-2026-32598CVSS 6.5 · MEDIUM

Summary: OneUptime versions prior to 10.0.24 log the complete password reset URL (including the plaintext token) at INFO level, enabling anyone with access to application logs to intercept tokens and hijack accounts.

Affected Features / Interoperability: The OneUptime password reset flow logging mechanism is affected; exposure could lead to account takeover across any integrated service.

Source: https://github.com/OneUptime/oneuptime/security/advisories/GHSA-4524-cj9j-g4fj

Actions:

  • Fix: Upgrade to OneUptime 10.0.24 or later.
  • Workaround: Restrict log access, disable INFO-level logging for password reset URLs, or implement log masking to omit tokens.
  • Tradeoff: Reduced visibility for debugging authentication flows.
