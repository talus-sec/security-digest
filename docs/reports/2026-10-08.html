Scoped Vulnerability Tracking

Database

The most urgent items this cycle are a cluster of CVSS 8.8 SQL-injection flaws affecting MySQL-backed applications (LimeSurvey RemoteControl API, Budibase column-rename DDL, and my little forum bookmark feature) and a PostgreSQL injection in OpenRemote’s crosstab export. All require authentication but allow stacked queries or data exfiltration with modest privileges. No CISA KEV entries appear in this dataset, so theoretical severity drives priority. Patch the application layers first—LimeSurvey, Budibase, OpenRemote, and my little forum—since the underlying database engines themselves only show medium-severity DoS bugs in this window.

Formal Vulnerabilities

MySQLCVE-2025-62606CVSS 8.8 · HIGH

Summary: An authenticated SQL injection in the bookmark reordering feature of my little forum (PHP/MySQL) prior to version 2.5.12 allows any logged-in user to execute arbitrary SQL commands, leading to full database compromise (read, modify, delete all data).

Affected Features / Interoperability: The bookmark reordering feature in my little forum application. Downstream impact includes complete compromise of the application’s database; no direct impact on MySQL replication, client drivers, or extensions.

Source: https://github.com/My-Little-Forum/mylittleforum/releases/tag/20251021.1, https://github.com/My-Little-Forum/mylittleforum/security/advisories/GHSA-m8hj-c6gr-6h6v

Actions:

  • Fix: Upgrade my little forum to version 2.5.12 or later.
  • Workaround: Disable the bookmark feature or restrict forum access to trusted users only.
  • Tradeoff: Disabling bookmarks removes user functionality; access restriction limits collaboration.
MySQLCVE-2026-50636CVSS 8.8 · HIGH

Summary: LimeSurvey’s RemoteControl API methods `invite_participants` and `remind_participants` concatenate a caller-supplied token-ID array into a SQL `IN` clause without parameterization. An authenticated attacker with `tokens/update` permission on a survey can inject stacked queries (INSERT/UPDATE/DELETE/DROP/CREATE) because PDO uses emulated prepares and MySQL multi-statements are enabled. This allows reading administrator password hashes, survey PII, sessions, and settings via time-based blind oracle, and overwriting hashes or dropping tables.

Affected Features / Interoperability: LimeSurvey RemoteControl API (RPCInterface = json/xml), which is not enabled by default. Impacts any schema the application’s database user can access. No direct impact on MySQL server components.

Source: https://github.com/LimeSurvey/LimeSurvey/pull/5031, https://www.limesurvey.org/, https://www.vulncheck.com/advisories/limesurvey-remotecontrol-invite-participants-remind-participants-sql-injection

Actions:

  • Fix: Apply the patch in LimeSurvey PR #5031 / upgrade to a version containing the fix.
  • Workaround: Disable the RemoteControl API (RPCInterface) if not required; otherwise restrict `tokens/update` permission to highly trusted accounts.
  • Tradeoff: Disabling RemoteControl breaks integrations that rely on programmatic survey participant management.
MySQLCVE-2026-100683CVSS 8.0 · HIGH

Summary: Budibase before 3.45.0 builds MySQL (and MSSQL) column-rename DDL by interpolating identifiers directly into raw query strings without using the project’s quoting helpers. An attacker with DDL rights on a connected datasource can create a column name containing a backtick (MySQL) or single quote (MSSQL) plus injected SQL; when a builder later renames that column via the UI, the payload executes as the datasource user. MySQL connection uses `multipleStatements: true`, enabling stacked statements.

Affected Features / Interoperability: Budibase column-rename operation (POST /api/tables with `_rename.old`). Impacts any MySQL/MSSQL datasource connected to Budibase; bypasses Budibase’s row/table permission model.

Source: https://github.com/Budibase/budibase/security/advisories/GHSA-ppj8-hmx2-m546, https://www.vulncheck.com/advisories/budibase-before-3.45.0-sql-injection-via-column-rename-ddl

Actions:

  • Fix: Upgrade Budibase to 3.45.0 or later.
  • Workaround: Restrict DDL rights on Budibase datasources; avoid allowing untrusted users to create/rename columns.
  • Tradeoff: Restricting DDL may break legitimate schema migration workflows.
MySQLCVE-2025-4203CVSS 7.5 · HIGH

Summary: The wpForo Forum plugin for WordPress ≤ 2.4.8 is vulnerable to error-based or time-based SQL injection via the `get_members()` function due to missing integer validation on `offset` and `row_count` parameters. Unauthenticated attackers can append a `PROCEDURE ANALYSE` clause after the `LIMIT` clause (MySQL 5.x grammar) to extract database data.

Affected Features / Interoperability: wpForo Members functionality (`classes/Members.php`). No direct MySQL server impact; WordPress site database exposure.

Source: https://plugins.trac.wordpress.org/browser/wpforo/tags/2.4.5/classes/Members.php#L1557, https://plugins.trac.wordpress.org/browser/wpforo/tags/2.4.9/classes/Members.php#L1557, https://wordpress.org/plugins/wpforo/#developers, https://www.wordfence.com/threat-intel/vulnerabilities/id/bc406e8a-c4eb-45c3-a53c-37644e0dabfa?source=cve

Actions:

  • Fix: Update wpForo to version 2.4.9 or later.
  • Workaround: Disable the wpForo plugin or restrict access to the members endpoint via WAF rules.
  • Tradeoff: Disabling wpForo removes forum functionality.

Summary: girishsaraf Online-Appointment-Booking-System (up to commit f427b47) has a SQL injection in `Admin/mlogin.php` via the `uname`/`pass` parameters passed to `mysqli_query`. The exploit is public; the project uses a rolling release with no versioned fix and has not responded to disclosure.

Affected Features / Interoperability: Login handler component. No versioned release data available; impact limited to this application’s database.

Source: https://github.com/girishsaraf/Online-Appointment-Booking-System/, https://github.com/girishsaraf/Online-Appointment-Booking-System/issues/6, https://vuldb.com/cve/CVE-2026-105468, https://vuldb.com/submit/984333, https://vuldb.com/vuln/413614

PostgreSQLCVE-2026-107314CVSS 5.9 · MEDIUM

Summary: pgjdbc (PostgreSQL JDBC Driver) versions 42.7.11–42.7.13: when `requireAuth` connection property excludes all six known auth methods (e.g., `requireAuth=!password,!md5,!gss,!sspi,!scram-sha-256,!none` or `requireAuth=,`), the driver accepts any server-requested method, including cleartext password. A MitM attacker can steal the database password.

Affected Features / Interoperability: JDBC driver authentication negotiation. Applications using affected driver versions with exclusion-only `requireAuth` values.

Source: https://github.com/pgjdbc/pgjdbc/security/advisories/GHSA-rhp9-mr79-r74h

Actions:

  • Fix: Upgrade pgjdbc to 42.7.14 or later.
  • Workaround: Use a positive-list `requireAuth` value (e.g., `requireAuth=scram-sha-256`) or unset the property (default is safe).
  • Tradeoff: Positive list requires knowing server-supported methods; unsetting removes explicit control.
PostgreSQLCVE-2026-107315CVSS 5.3 · MEDIUM

Summary: pgjdbc versions 42.7.4–42.7.13 pad short values with leftover send-buffer bytes (up to 8192 bytes, 16320 with GSS) instead of zeros. The padding contains prior SQL text and parameter values from the same pooled connection. An attacker who can store and read back such a value can collect earlier traffic.

Affected Features / Interoperability: PreparedStatement.setObject with ByteStreamWriter, CopyIn.writeToCopy, PGCopyOutputStream.write, LargeObject.write, Blob.setBytes when declared length exceeds supplied data. Connection pooling amplifies cross-request leakage.

Source: https://github.com/pgjdbc/pgjdbc/security/advisories/GHSA-f64h-wr5q-3qf3

Actions:

  • Fix: Upgrade pgjdbc to 42.7.14 or later.
  • Workaround: Ensure declared lengths always match supplied data; avoid the affected API patterns.
  • Tradeoff: Code changes may be needed in application data-access layer.
PostgreSQLCVE-2026-107313CVSS 4.2 · MEDIUM

Summary: pgjdbc versions 42.7.4 and 42.7.5 on GSS-encrypted connections (`gssEncMode=prefer` or `require`) can send previous GSS send-buffer contents (up to 16320 bytes) as the first part of a value. The stored value contains prior SQL text, parameters, or batch rows. Most such writes fail with `ArrayIndexOutOfBoundsException`. Default `gssEncMode=allow` is not affected.

Affected Features / Interoperability: GSS-encrypted connections with specific bind-parameter APIs (setString, setBytes, ByteStreamWriter, CopyIn, LargeObject.write). Only versions 42.7.4–42.7.5.

Source: https://github.com/pgjdbc/pgjdbc/commit/96f6862bb6bcadde7620688c7bce73f2d01a7ebb, https://github.com/pgjdbc/pgjdbc/pull/3500, https://github.com/pgjdbc/pgjdbc/security/advisories/GHSA-hggc-j2qh-988m

Actions:

  • Fix: Upgrade pgjdbc to 42.7.6 or later (or downgrade to ≤ 42.7.3).
  • Workaround: Set `gssEncMode=allow` (default) to avoid GSS encryption; or avoid affected API calls.
  • Tradeoff: Disabling GSS encryption removes Kerberos-integrated auth encryption.
