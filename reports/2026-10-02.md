# Security Digest — 2026-10-02

## Database

The single most urgent item this cycle is CVE-2026-103253 (CVSS 8.7, HIGH) affecting the Oracle Database node in n8n, which permits SQL injection via the Delete Table Drop operation, allowing arbitrary DDL/DML execution against connected databases using the credential's privileges. While no entries in this digest are currently flagged as CISA KEV-confirmed, CVE-2024-58374 (Microsoft SQL Server scope) carries observed exploitation evidence from the Shadowserver Foundation, and CVE-2026-104457 (MySQL scope) presents an unauthenticated SQL injection risk on default YesWiki installs. Given the healthcare environment, any workflow automation (n8n) or patient-facing wiki endpoints (YesWiki) connected to clinical databases require immediate review, alongside the MobilityDB denial-of-service risk for PostgreSQL instances in the homelab.

### Formal Vulnerabilities

#### MySQL — CVE-2026-104457 (CVSS 8.6 HIGH)
**Summary:** YesWiki before 4.6.7 contains an SQL injection vulnerability in the Bazar filtertags action, where unescaped filterN attribute tokens are wrapped in quotes and concatenated into a raw tags.value IN (...) clause. Unauthenticated attackers on default installs can save filtertags markup with a trailing-backslash token to break quote parity under MySQL backslash escaping, enabling a five-column UNION subquery to read arbitrary table data such as password hashes.

**Affected Features / Interoperability:** Bazar filtertags action and page markup parsing. Downstream impact includes potential exposure of user credentials and arbitrary data read from the connected MySQL database, affecting any YesWiki deployment integrated with patient or staff data.

**Source:**
- https://github.com/YesWiki/yeswiki/security/advisories/GHSA-p87r-f4x4-8r4g
- https://www.vulncheck.com/advisories/yeswiki-before-4.6.7-sql-injection-via-filtertags-filtern-parameter

**Actions:**
- Fix: Upgrade YesWiki to version 4.6.7 or later.
- Workaround: Disable the Bazar filtertags action or prevent unauthenticated page saves on public-facing instances.
- Tradeoff: Disabling the action removes filtertag functionality for page organization.

#### MySQL — CVE-2026-103231 (CVSS 7.3 HIGH)
**Summary:** The Restaurant-Management-System up to commit 7f0e7e84255e8fcfd488e83f8f91451bbbff6b9c contains an SQL injection in the mysqli_query function of User/cancel.php within the Order Cancellation component. The manipulation of the ID argument leads to SQL injection, and the attack may be initiated remotely; the exploit is publicly available.

**Affected Features / Interoperability:** Order Cancellation component and the mysqli_query database call. Downstream impact includes unauthorized data manipulation or extraction from the connected database via the order cancellation workflow.

**Source:**
- https://github.com/AdithyaYelloju/Restaurant-Management-System/
- https://github.com/AdithyaYelloju/Restaurant-Management-System/issues/7
- https://vuldb.com/cve/CVE-2026-103231
- https://vuldb.com/submit/955080
- https://vuldb.com/vuln/411924

**Actions:**
- Fix: Upgrade past commit 7f0e7e84255e8fcfd488e83f8f91451bbbff6b9c.
- Workaround: Restrict network access to the User/cancel.php endpoint and the Order Cancellation component.
- Tradeoff: Order cancellation functionality is impacted for restricted users or networks.

#### MySQL — CVE-2025-53067 (CVSS 4.9 MEDIUM)
**Summary:** Vulnerability in the MySQL Server product of Oracle MySQL (component: Server: Optimizer). Supported versions 9.0.0-9.4.0 are affected by an easily exploitable vulnerability allowing a high-privileged attacker with network access via multiple protocols to compromise MySQL Server. Successful attacks result in unauthorized ability to cause a hang or frequently repeatable crash (complete DOS) of MySQL Server.

**Affected Features / Interoperability:** MySQL Server Optimizer component. Downstream impact is denial of service affecting the entire instance, which could disrupt replication, client connections, and dependent applications relying on database availability.

**Source:**
- https://www.oracle.com/security-alerts/cpuoct2025.html

**Actions:**
- Fix: Apply the Oracle Critical Patch Update (CPU) October 2025.
- Workaround: Restrict network access to MySQL Server to high-privileged users only, as the vulnerability requires high privilege.
- Tradeoff: No significant tradeoff.

#### PostgreSQL — CVE-2026-102639 (CVSS 6.5 MEDIUM)
**Summary:** MobilityDB version 1.3.0 and earlier contains an out-of-bounds read vulnerability in the MEOS binary and library WKB deserialization logic. Unprivileged database users can crash the PostgreSQL backend process by supplying a crafted WKB payload with a negative length field, causing memcpy() to operate with a corrupted unbounded length and resulting in a remote denial-of-service condition affecting all sessions on the instance.

**Affected Features / Interoperability:** MobilityDB MEOS binary/library WKB deserialization. Downstream impact affects all sessions on the PostgreSQL instance, including replication and any geospatial time-series analytics relying on the MobilityDB extension.

**Source:**
- https://github.com/MobilityDB/MobilityDB/releases/tag/v1.2.2
- https://github.com/MobilityDB/MobilityDB/releases/tag/v1.3.1
- https://github.com/MobilityDB/MobilityDB/security/advisories/GHSA-2c92-2w7c-pm3g
- https://www.vulncheck.com/advisories/mobilitydb-through-out-of-bounds-read-dos-via-wkb-deserialization

**Actions:**
- Fix: Upgrade MobilityDB to v1.3.1 (or v1.2.2 per advisory).
- Workaround: Disable the MobilityDB extension in PostgreSQL instances not requiring geospatial time-series features.
- Tradeoff: Disabling the extension removes MEOS binary/library WKB deserialization capabilities and associated geospatial analytics.

#### Oracle Database — CVE-2026-103253 (CVSS 8.7 HIGH)
**Summary:** n8n versions before 1.123.80, from 2.0.0 before 2.39.6, and from 2.40.0 before 2.40.1 contain an SQL injection vulnerability in the Oracle Database node's Delete Table Drop operation. Attackers can inject single quotes in the table or schema fields to append arbitrary SQL statements and execute DDL or DML commands against the connected database with the credential's privileges.

**Affected Features / Interoperability:** n8n Oracle Database node, specifically the Delete Table Drop operation. Downstream impact includes arbitrary DDL/DML execution against connected Oracle databases, risking data integrity, schema modification, and credential theft via the workflow service account.

**Source:**
- https://github.com/n8n-io/n8n/security/advisories/GHSA-4wf3-rgqr-xcp3
- https://www.vulncheck.com/advisories/n8n-before-1.123.80-2.39.6-and-2.40.1-sql-injection-via-oracle-database-drop-table

**Actions:**
- Fix: Upgrade n8n to 1.123.80 or later, or 2.39.6/2.40.1 or later depending on the branch.
- Workaround: Remove the Oracle Database node from workflows or restrict n8n service account credentials to least privilege.
- Tradeoff: Removing the node breaks Oracle integration workflows; credential restriction limits automation scope.

#### Oracle Database — CVE-2026-104460 (CVSS 7.5 HIGH)
**Summary:** YesWiki before 4.6.7 contains a blind SQL injection vulnerability in the {{newtextsearch}} action because Bazar list option ids are concatenated into SQL REGEXP/LIKE clauses in actions/newtextsearch.php without escaping. Anonymous attackers can plant a malicious option id in an anonymously editable Bazar list and use search requests as a boolean oracle to read arbitrary database data, including admin password hashes from the yeswiki_users table.

**Affected Features / Interoperability:** Bazar list option ids and the newtextsearch action. Downstream impact includes blind data exfiltration from the connected database, including administrative credentials, affecting any YesWiki deployment integrated with sensitive data.

**Source:**
- https://github.com/YesWiki/yeswiki/security/advisories/GHSA-4333-x9p4-8xj7
- https://www.vulncheck.com/advisories/yeswiki-before-4.6.7-unauthenticated-blind-sql-injection-via-newtextsearch

**Actions:**
- Fix: Upgrade YesWiki to version 4.6.7 or later.
- Workaround: Disable anonymous editing of Bazar lists or restrict the newtextsearch action.
- Tradeoff: Loss of anonymous search and edit functionality.

#### Microsoft SQL Server — CVE-2024-58374 (CVSS 7.5 HIGH)
**Summary:** Hongjing e-HR contains an unauthenticated SQL injection vulnerability in the getSdutyTree servlet endpoint that allows remote unauthenticated attackers to access protected resources by supplying a path traversal sequence in the request URI to bypass the oauthservlet authentication filter. Attackers can inject UNION-based SQL payloads through the unsanitized codeitemid parameter into the underlying Microsoft SQL Server query to retrieve sensitive database contents including user credentials. Exploitation evidence was first observed by the Shadowserver Foundation on 2024-07-30 (UTC).

**Affected Features / Interoperability:** getSdutyTree servlet endpoint and oauthservlet authentication filter. Downstream impact includes unauthorized access to protected resources and retrieval of user credentials from the connected Microsoft SQL Server, affecting HR and personnel data systems.

**Source:**
- https://cn-sec.com/archives/2926383.html
- https://www.ddpoc.com/DVB-2024-7391.html
- https://www.vulncheck.com/advisories/hongjing-e-hr-unauthenticated-sql-injection-via-getsdutytree

**Actions:**
- Fix: None provided in available advisory data.
- Workaround: Block external network access to the getSdutyTree servlet endpoint and enforce the oauthservlet authentication filter.
- Tradeoff: Duty tree access is unavailable from untrusted networks.
