# Security Digest — 2026-09-03

## Database

The most urgent item this period is **CVE-2026-9586**, a CISA KEV-confirmed SQL injection in Sangoma Switchvox with an arbitrary code execution vector and a federal due date of September 5, 2026. While this targets a third-party application (not PostgreSQL directly), any homelab or enterprise environment where Switchvox's backend PostgreSQL database is exposed to untrusted input faces confirmed, active exploitation. Treat this as an emergency patch cycle.

### Formal Vulnerabilities

#### MySQL — CVE-2026-60592 (CVSS 8.2 HIGH)
**Summary:** A flaw in MySQL Cluster's NDB Operator allows an unauthenticated remote attacker over the network to crash the cluster or corrupt data via unauthorized inserts, updates, or deletes. No authentication is required, and the attack surface is exposed via standard cluster protocols.

**Affected Features / Interoperability:** MySQL Cluster component (NDB Operator) in versions 8.0.0–8.0.47, 8.4.0–8.4.10, and 9.7.0–9.7.1. Impacts cluster availability and data integrity; affects replication and failover operations.

**Source:** https://www.oracle.com/security-alerts/cspuaug2026.html

**Actions:**
- Fix: Apply the patched version released in Oracle's August 2026 Critical Patch Update.
- Workaround: Restrict network access to MySQL Cluster management ports; enforce TLS for cluster communications.
- Tradeoff: Network restrictions may disrupt legitimate cluster management workflows requiring careful allowlist management.

#### MySQL — CVE-2026-71084 (CVSS 6.8 MEDIUM)
**Summary:** A vulnerability in MySQL Connector/ODBC version 26.7.0 allows an unauthenticated attacker with local access to the host to crash the connector and read a subset of accessible data.

**Affected Features / Interoperability:** MySQL Connector/ODBC component; affects applications using ODBC connections to MySQL databases. Data exposure is limited to data accessible through the connector's connection context.

**Source:** https://www.oracle.com/security-alerts/cspuaug2026.html

**Actions:**
- Fix: Apply the patched version released in Oracle's August 2026 Critical Patch Update.
- Workaround: Limit local access to systems running ODBC-based MySQL client applications.
- Tradeoff: Restrictive host access may impede legitimate ODBC-based reporting or ETL workflows.

#### MySQL — CVE-2026-19475 (CVSS 6.5 MEDIUM)

**Affected Features / Interoperability:** Grafana's MySQL (and PostgreSQL/MSSQL) data source query processing. Affects visualization and monitoring workflows; does not directly corrupt database data but disrupts availability of Grafana-linked dashboards.

#### PostgreSQL — CVE-2026-9586 (CVSS 9.8 CRITICAL) 🔴 ACTIVELY EXPLOITED (CISA KEV)
**Summary:** An unauthenticated remote SQL injection in Sangoma Switchvox SMB Edition 8.3 allows attackers to execute arbitrary SQL statements on the backend PostgreSQL database—including operating system command execution—via a crafted request to the `/pa` endpoint. This is confirmed actively exploited in the wild and carries a federal remediation deadline of September 5, 2026.

**Affected Features / Interoperability:** Sangoma Switchvox's `/pa` endpoint that processes XML with the `PhoneIP` parameter. The underlying PostgreSQL database is exposed to unauthorized query execution; any data in that database (call records, credentials, configurations) is at risk. mTLS and Vault PKI infrastructure in the homelab could be indirectly impacted if Switchvox shares credential stores.

**Source:**
- https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-9586
- https://horizon3.ai/attack-research/disclosures/cve-2026-9586-sangoma-switchvox-rce/#

**Actions:**
- Fix: Upgrade to Sangoma Switchvox version 8.4.0.2 (released July 14, 2026) or later per the vendor advisory.
- Workaround: If the product cannot be immediately updated, isolate the `/pa` endpoint from untrusted networks; block external access to the Switchvox management interface.
- Tradeoff: Isolating the endpoint may disrupt legitimate remote management; upgrade is the definitive fix.

#### MongoDB — CVE-2026-84970 (CVSS 6.2 MEDIUM)
**Summary:** The MongoDB C++ Driver's BSON JSON parsing library can read beyond the supplied buffer, silently truncate large inputs, or crash when processing oversized JSON. An attacker controlling input to the library's public API (no MongoDB server credentials needed) can trigger these behaviors. This affects any application using the driver to parse untrusted JSON.

**Affected Features / Interoperability:** The C++ driver's JSON parsing interface; affects MongoDB client applications ingesting JSON from external sources. Does not impact the MongoDB server itself.

**Source:** https://jira.mongodb.org/browse/CXX-3547

**Actions:**
- Fix: Upgrade to the patched MongoDB C++ Driver version per the vendor advisory.
- Workaround: Validate and cap JSON input sizes before passing to the driver; sanitize external JSON sources.
- Tradeoff: Input validation adds latency and may reject legitimate large documents.

#### MongoDB — CVE-2026-84969 (CVSS 3.7 LOW)
**Summary:** A memory-handling flaw in the MongoDB C Driver's BSON-to-JSON conversion can write a few bytes past a heap buffer's boundary when binary fields are encoded with a caller-configured output length limit. This is a minor data integrity issue with limited exploitability.

**Affected Features / Interoperability:** The C driver's binary encoding path; affects applications using BSON-to-JSON conversion with tight output size constraints.

**Source:** https://jira.mongodb.org/browse/CDRIVER-6410

**Actions:**
- Fix: Upgrade to the patched MongoDB C Driver version.
- Workaround: Avoid tight output length limits in binary encoding contexts; ensure applications handle encoding errors gracefully.
- Tradeoff: Minimal; low-severity issue unlikely to impact most deployments.

## Cloud Security

Today's digest carries one confirmed-active, in-the-wild item that demands immediate action: **CVE-2026-66384 (JFrog Artifactory path-traversal)** is on the CISA KEV catalog with a due date of **2026-09-10**, affecting Docker cache path handling under specific remote-repository configurations — anything pulling JFrog Artifactory as a Docker image registry needs to be triaged now. Beyond that KEV hit, the high-CVSS cluster is dominated by Kubernetes control-plane and ingress flaws: an OpenChoreo cross-project exec/wirelogs authorization bypass (CVE-2026-73841, 8.8), an RHACM service-proxy header-injection path to cluster-admin on every managed cluster (CVE-2026-17107, 8.5), and an NGINX Ingress annotation injection control-plane issue (CVE-2026-77180, 8.3) are the highest-impact cluster-side items. In Microsoft Azure land, a Jenkins Entra ID plugin flaw (CVE-2026-84672, 8.8) lets a crafted Entra group display name collide with a privileged group and inherit its role — relevant wherever Azure-hosted Jenkins is used for CI/CD. News chatter (separate from formal advisories) flags AI-coding-agent supply-chain risks via malicious `.git` configs and SonicWall SMA 1000 zero-day chaining, both worth tracking even though no CVE is being claimed from those items here.

### Formal Vulnerabilities

#### Docker — CVE-2026-66384 (CVSS UNSCORED — CISA-confirmed active exploitation) 🔴 ACTIVELY EXPLOITED (CISA KEV)
**Summary:** CISA-confirmed active exploitation (added to KEV 2026-08-27, due date **2026-09-10**) of an improper path-restriction flaw in JFrog Artifactory that lets an authenticated user write data outside the intended Docker cache path when specific remote-repository conditions are met. Exploitation requires a valid Artifactory account; no unauthenticated path is described in the available data.

**Affected Features / Interoperability:** Docker image caching paths when Artifactory fronts remote Docker repositories — anything pushing/pulling container images through affected remote-repository configurations. Downstream: cache integrity, image provenance, and potential lateral file writes on the Artifactory host.

**Source:** https://nvd.nist.gov/vuln/detail/CVE-2026-66384

**Actions:**
- Fix: No official patched version is named in the supplied KEV entry — follow JFrog's vendor instructions and CISA's BOD 26-04 guidance.
- Workaround: Restrict authenticated users on Artifactory instances fronting Docker remote repositories; review/limit who can write to Docker cache paths; audit recent writes outside expected cache locations.
- Tradeoff: Tightening authenticated-user rights may break legitimate developer workflows that rely on shared remote-repo write access — coordinate with CI/CD owners before locking down.

#### Docker — CVE-2026-79755 (CVSS 8.0 HIGH)
**Summary:** On the Nuclio local Docker platform, an unvalidated `namespace` value is interpolated into a shell-quoted `docker ps` command run via `/bin/sh -c` on the dashboard host. Default auth is `nop` (unauthenticated), so a remote attacker can inject arbitrary OS commands that execute as root inside the dashboard container — which holds the Docker socket, yielding host-level compromise. Fixed in Nuclio 1.17.4.

**Affected Features / Interoperability:** Nuclio dashboard on the local Docker platform — Docker socket access, container lifecycle, host shell. Downstream: any workloads running on a Nuclio-managed local Docker host.

**Source:** https://github.com/nuclio/nuclio/security/advisories/GHSA-2893-rq73-w22x

**Actions:**
- Fix: Upgrade Nuclio to **1.17.4** or later.
- Workaround: Disable `nop` auth and require authentication on the Nuclio dashboard until upgrade; restrict network reachability to the dashboard.
- Tradeoff: Enabling authentication breaks any existing automation relying on unauthenticated local Nuclio access — provision replacement credentials/scripts first.

#### Microsoft Azure — CVE-2026-84672 (CVSS 8.8 HIGH)
**Summary:** Jenkins Microsoft Entra ID (previously Azure AD) Plugin 710.v0b_ff8e9cc2d2 and earlier grants Entra group permissions using both the group's unique object ID and its display name. An attacker able to create an Entra group with a display name that collides with a privileged group can inherit that group's configured Jenkins permissions. Exploitation requires Entra tenant write access (i.e., ability to create groups in the tenant); the auth surface is therefore "who can create groups in your Entra directory."

**Affected Features / Interoperability:** Jenkins authorization integrations where Entra group → Jenkins role mapping is configured via the Microsoft Entra ID plugin on Jenkins instances hosted in or federated to Azure. Downstream: Jenkins job execution, pipeline secrets, build artifact stores, deployment credentials reachable from a compromised Jenkins node.

**Source:** https://www.jenkins.io/security/advisory/2026-09-02/#SECURITY-3935

**Actions:**
- Fix: Upgrade the Jenkins Microsoft Entra ID Plugin to a version newer than 710.v0b_ff8e9cc2d2 (advisory lists the fix; exact version not provided in the supplied data — consult the Jenkins advisory).
- Workaround: Audit Entra tenant for groups whose display names collide with privileged group names; restrict who can create Entra groups; prefer object-ID-based mappings once available.
- Tradeoff: Restricting group-creation rights will impact legitimate IT workflows that rely on user-created Entra groups — coordinate with identity team before tightening.

#### Kubernetes — CVE-2026-73841 (CVSS 8.8 HIGH)
**Summary:** OpenChoreo (an open-source Kubernetes developer platform) prior to 1.1.6 / 1.2.3 authorizes `component:exec` and `wirelogs:view` against the **caller-supplied** `project` query parameter rather than the component's actual owning project (`comp.Spec.Owner.ProjectName`). A user with a project-scoped grant in one project can therefore execute commands in and read wirelogs from components owned by **other projects in the same namespace**. Exploitation requires an authenticated principal with any project-scoped OpenChoreo grant.

**Affected Features / Interoperability:** OpenChoreo `component:exec` (in-cluster command execution against component pods) and `wirelogs:view` (reading wire logs). Downstream: any tenant isolation guarantees for OpenChoreo projects sharing a namespace; cross-tenant debug/log access.

**Source:** https://github.com/openchoreo/openchoreo/commit/4d372eaf1f07525663dcca5257062f4b051b9820 ; https://github.com/openchoreo/openchoreo/commit/9d77b64f747eba89247c47ebfeffec591c4cd2d8 ; https://github.com/openchoreo/openchoreo/commit/c9390e4fcb9953f43b07cb48197576182301593d ; https://github.com/openchoreo/openchoreo/pull/4251 ; https://github.com/openchoreo/openchoreo/pull/4516

**Actions:**
- Fix: Upgrade OpenChoreo to **1.1.6** or **1.2.3** (or later).
- Workaround: Until patched, restrict who can be granted project-scoped OpenChoreo roles in shared namespaces; consider isolating projects into separate namespaces at the Kubernetes RBAC layer (note: this only partially mitigates since the bug is OpenChoreo-level, not K8s RBAC).
- Tradeoff: Forcing namespace-per-project reduces OpenChoreo's multi-tenant density and increases cluster resource overhead.

#### Kubernetes — CVE-2026-17107 (CVSS 8.5 HIGH)
**Summary:** In Red Hat Advanced Cluster Management for Kubernetes (RHACM) and multicluster-engine (MCE), the cluster-proxy `service-proxy` component appends impersonation-group headers to proxied requests **without first stripping caller-supplied values**, and the spoke ServiceAccount holds unrestricted impersonation rights. An authenticated hub principal can inject an `Impersonate-Group` header and escalate to `cluster-admin` on **every** managed cluster reachable via the proxy. Exploitation requires any authenticated principal on the hub cluster.

**Affected Features / Multi-cluster Interoperability:** RHACM/MCE service-proxy across hub → spoke communication; ultimately every managed cluster that the hub can reach via service-proxy. Downstream: cluster-admin on all spokes — total Kubernetes control-plane compromise of the fleet.

**Source:** https://access.redhat.com/errata/RHSA-2026:46885 ; https://access.redhat.com/errata/RHSA-2026:47388 ; https://access.redhat.com/errata/RHSA-2026:47735 ; https://access.redhat.com/errata/RHSA-2026:47949 ; https://access.redhat.com/errata/RHSA-2026:47953

**Actions:**
- Fix: Apply RHSA-2026:46885 / 47388 / 47735 / 47949 / 47953 (or later) per Red Hat's errata for your RHACM/MCE version.
- Workaround: Until patched, restrict who can authenticate to the hub cluster-proxy endpoint; front the service-proxy with an auth proxy that strips `Impersonate-*` headers from inbound requests; review hub audit logs for unexpected `Impersonate-Group` headers.
- Tradeoff: Header-stripping at an ingress proxy may break legitimate RHACM multi-cluster operations that rely on user impersonation — coordinate with cluster-ops before deploying.

**Affected Features / Interoperability:** NGINX Ingress Controller configuration generation; downstream any service fronted by NGINX Ingress whose annotations can be written by untrusted users.

#### Kubernetes — CVE-2026-52831 (CVSS 8.0 HIGH)

- Tradeoff: Restricting trigger-creation rights will slow down legitimate scheduled-job onboarding — pair with a code-review gate on trigger specs.

#### Kubernetes — CVE-2026-66781 (CVSS 5.4 MEDIUM)
**Summary:** The Submariner operator stores the IPsec pre-shared key (PSK) used to secure cross-cluster mesh traffic **in plaintext** within the Submariner Custom Resource. Anyone able to read the CR can passively decrypt traffic between any two clusters in the mesh. Disclosure requires read access to the Submariner CR — typically cluster-admin or namespace-scoped operator access.

**Affected Features / Interoperability:** Submariner IPsec tunnels between Kubernetes clusters in a mesh; downstream: confidentiality of all cross-cluster traffic carried over those tunnels.

**Source:** https://access.redhat.com/errata/RHSA-2026:60386 ; https://access.redhat.com/errata/RHSA-2026:60387 ; https://access.redhat.com/errata/RHSA-2026:60388 ; https://access.redhat.com/errata/RHSA-2026:60389 ; https://access.redhat.com/errata/RHSA-2026:60390

**Actions:**
- Fix: Apply RHSA-2026:60386–60390 (or later) per Red Hat's errata.
- Workaround: Rotate PSKs and treat any previously exposed PSK as compromised; restrict RBAC on the Submariner CR namespace; consider migrating to a secrets manager that does not persist the key in a CR.
- Tradeoff: PSK rotation will briefly disconnect tunnel peers until both ends are updated — schedule a maintenance window.

#### Kubernetes — CVE-2026-79754 (CVSS UNSCORED)
**Summary:** Nuclio Dashboard's build pipeline does not sanitize `spec.build.tempDir` before using it to construct a shell command. With the Kaniko container builder enabled, a user with function-create permission can inject shell metacharacters into `tempDir` and achieve arbitrary command execution inside the Dashboard container — which runs with a Kubernetes service account holding **wildcard** access to Secrets, Pods, Jobs, and Deployments in its namespace. Affects Nuclio 1.6.19 through 1.17.1; fixed in **1.17.2**.

**Affected Features / Interoperability:** Nuclio Dashboard + Kaniko builder pipeline; downstream: full namespace-level access to Secrets, Pods, Jobs, and Deployments for any user with function-create.

**Source:** https://github.com/nuclio/nuclio/security/advisories/GHSA-x44h-qmrv-mh72 ; https://github.com/nuclio/nuclio/releases/tag/1.17.2

**Actions:**
- Fix: Upgrade Nuclio to **1.17.2** or later (1.17.4 also covers CVE-2026-79755 above; prefer 1.17.4 if available).
- Workaround: Restrict who can create functions; disable the Kaniko builder path until patched; review function specs for suspicious `spec.build.tempDir` values.
- Tradeoff: Disabling the Kaniko builder will break function-build pipelines that rely on it — coordinate with application teams before disabling.
