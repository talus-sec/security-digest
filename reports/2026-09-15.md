## Cloud Security

**Executive Summary:** The most urgent items this cycle are two CRITICAL (CVSS 9.8) vulnerabilities in Kubernetes ecosystem components: Apache Camel K (CVE-2026-80352) and Traefik (CVE-2026-88877), both enabling unauthorized access through distinct vectors—YAML-based code injection and authentication bypass, respectively. Docker also carries a CRITICAL (CVSS 9.6) IBM Langflow SSRF-to-RCE chain and a HIGH (CVSS 7.8) Apache Storm worker-launcher privilege escalation issue that warrant prompt attention.

### Formal Vulnerabilities

#### Kubernetes — CVE-2026-80352 (CVSS 9.8 CRITICAL)
**Summary:** Apache Camel K contains a YAML injection vulnerability in custom resource configuration. An authorized CR author can inject arbitrary Kubernetes objects, potentially enabling unauthorized resource creation with the operator's privileges.

**Affected Features / Interoperability:** Camel K custom resource definitions and operator reconciliation pipeline. Any workload relying on CR-based configuration (integrations, deployments, routes) could be subverted to create resources outside intended scope.

**Source:** https://camel.apache.org/security/CVE-2026-80352.html, http://www.openwall.com/lists/oss-security/2026/09/10/15

**Actions:**
- Fix: Upgrade to Camel K 2.9.3, 2.10.2, or 2.11.0
- Workaround: Restrict CR author permissions to trusted principals; validate CR payloads before submission
- Tradeoff: Tighter RBAC may slow legitimate self-service integration deployments

#### Kubernetes — CVE-2026-88877 (CVSS 9.8 CRITICAL)
**Summary:** In Traefik v3.7.0–v3.7.11, the Kubernetes ingress-nginx provider mishandles Ingresses carrying both an authentication annotation and the `nginx.ingress.kubernetes.io/from-to-www-redirect` annotation. A sibling router is created that matches on host alone, lacks terminal redirect handling, and proxies requests to the protected backend with all annotation-derived middlewares (including authentication and source-IP allowlisting) stripped.

**Affected Features / Interoperability:** Traefik ingress routing for Ingress resources using both auth and redirect annotations. Authentication (e.g., BasicAuth), source-IP filtering, and any other annotation-derived middleware are bypassed for matching requests.

**Source:** https://github.com/traefik/traefik/security/advisories/GHSA-cjr6-pf59-jq29, https://www.vulncheck.com/advisories/traefik-3.7.0-authentication-bypass-via-from-to-www-redirect

**Actions:**
- Fix: Upgrade to Traefik v3.7.12 (v2 and v3 before v3.7.0 are not affected)
- Workaround: Remove the `from-to-www-redirect` annotation from Ingresses or avoid combining it with authentication annotations
- Tradeoff: Loss of the redirect functionality on affected Ingresses until upgraded
