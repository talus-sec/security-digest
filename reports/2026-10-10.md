# Security Digest — 2026-10-10

## Database
The most urgent database issue is the stack‑buffer‑overflow in MariaDB’s CONNECT engine (CVE‑2026-107815, CVSS 8.5 HIGH), which allows an authenticated user with access to the CONNECT engine to crash the server and potentially achieve remote code execution; patching to the fixed MariaDB releases is the priority.

### Formal Vulnerabilities

#### MySQL — CVE-2026-107815 (CVSS 8.5 HIGH)
**Summary:** In MariaDB server versions 10.6.1‑10.6.28, 10.11.1‑10.11.19, 11.4.1‑11.4.13, 11.8.1‑11.8.9, 12.3.1‑12.3.3, and 13.0.1‑13.0.2, the CONNECT engine’s DOS table type performs an incorrect boundary check, permitting a one‑byte null write beyond a stack buffer at an attacker‑controlled offset. An authenticated user who can use the CONNECT engine can trigger a crash and possibly remote code execution.  
**Affected Features / Interoperability:** The CONNECT storage engine; impacts any functionality relying on that engine (e.g., federated tables, specific ODBC/JDBC connectors). Replication, backup, or client‑driver operations that use CONNECT‑based tables could fail or be exploited.  
**Source:**  
- https://github.com/MariaDB/server/commit/b369925f6855d3e1f0ebcf453492724b99fda6f8  
- https://github.com/MariaDB/server/releases/tag/mariadb-10.11.19  
- https://github.com/MariaDB/server/releases/tag/mariadb-10.6.28  
- https://github.com/MariaDB/server/releases/tag/mariadb-11.4.13  
- https://github.com/MariaDB/server/releases/tag/mariadb-11.8.9  
**Actions:**  
- Fix: Upgrade to MariaDB 10.6.28, 10.11.19, 11.4.13, 11.8.9, 12.3.3, or 13.0.2 (or later).  
- Workaround: Disable the CONNECT engine if not required, or restrict CONNECT usage to trusted accounts.  
- Tradeoff: Disabling CONNECT may break applications that depend on its table‑access features.

#### MySQL — CVE-2026-107814 (CVSS 8.4 HIGH)
**Summary:** In the same version ranges, MariaDB RPM packages set the mysql service account’s home directory to the database data directory. A user with the FILE privilege could write dot‑files (e.g., .bash_profile) into $HOME, which would execute when an administrator logs in as the mysql account, leading to privilege escalation. Debian packages are unaffected.  
**Affected Features / Interoperability:** Service account configuration for the mysql system user; affects any administrative login or automation that relies on the mysql account’s environment.  
**Source:**  
- https://github.com/MariaDB/server/commit/d842d6e994a8b0d67c280bf785a11357d6b316a2  
- https://github.com/MariaDB/server/releases/tag/mariadb-10.11.19  
- https://github.com/MariaDB/server/releases/tag/mariadb-10.6.28  
- https://github.com/MariaDB/server/releases/tag/mariadb-11.4.13  
- https://github.com/MariaDB/server/releases/tag/mariadb-11.8.9  
**Actions:**  
- Fix: Upgrade to the patched MariaDB versions listed above.  
- Workaround: Change the mysql service account’s home directory to a non‑writable location (e.g., /nonexistent) and ensure the FILE privilege is not granted to untrusted users.  
- Tradeoff: Altering the home directory may break scripts that rely on the default location; restricting FILE privilege limits legitimate administrative tasks.

#### MySQL — CVE-2026-107818 (CVSS 8.4 HIGH)
**Summary:** In the affected releases, the mariadb.service unit references /run/mysqld/wsrep-new-cluster on restart. A user with the FILE privilege and permission to write to /run/mysqld (via secure‑file‑priv) can create that file and inject arbitrary environment variables into the restarted service, potentially leading to privilege escalation or code execution.  
**Affected Features / Interoperability:** Systemd service unit for MariaDB; impacts service startup, clustering (Galera/Wsrep), and any automation that depends on the service environment.  
**Source:**  
- https://github.com/MariaDB/server/commit/e3d62d4e78fd4941cef3f5053e6a50d0b32d740e  
- https://github.com/MariaDB/server/releases/tag/mariadb-10.11.19  
- https://github.com/MariaDB/server/releases/tag/mariadb-10.6.28  
- https://github.com/MariaDB/server/releases/tag/mariadb-11.4.13  
- https://github.com/MariaDB/server/releases/tag/mariadb-11.8.9  
**Actions:**  
- Fix: Upgrade to MariaDB 10.6.28, 10.11.19, 11.4.13, 11.8.9, 12.3.3, or 13.0.2.  
- Workaround: Restrict write access to /run/mysqld and ensure the secure‑file‑priv setting does not allow writes to that directory; avoid granting FILE privilege to untrusted users.  
- Tradeoff: Tightening filesystem permissions may interfere with legitimate backup or monitoring scripts that need to write to /run/mysqld.

#### MySQL — CVE-2026-107384 (CVSS 8.1 HIGH)
**Summary:** MariaDB Connector/Node.js versions 3.2.0‑3.2.5, 3.3.4, 3.4.7, and 3.5.4 improperly handle the permitSetMultiParamEntries option: attacker‑controlled object keys containing backticks can escape identifier quoting and be interpreted as SQL, allowing unintended column updates or arbitrary SQL execution when the option is enabled.  
**Affected Features / Interoperability:** Node.js applications using mariadb-connector-nodejs with permitSetMultiParamEntries enabled; impacts any data‑access layer that builds dynamic SET clauses.  
**Source:**  
- https://github.com/mariadb-corporation/mariadb-connector-nodejs/commit/144b8f4ef29539a9fb4b75d972b9dcdac4088b4e  
- https://github.com/mariadb-corporation/mariadb-connector-nodejs/commit/6743b2f4a89b074268b44c650170767f35e1fb5d  
- https://github.com/mariadb-corporation/mariadb-connector-nodejs/commit/8eb450972ff0f3826d7d45c071a42240798bc826  
- https://github.com/mariadb-corporation/mariadb-connector-nodejs/commit/b9b04ec82a60b2caf2b0c038259ca9aff5d7014a  
- https://github.com/mariadb-corporation/mariadb-connector-nodejs/releases/tag/3.2.5  
**Actions:**  
- Fix: Upgrade the connector to 3.2.5, 3.3.4, 3.4.7, or 3.5.4.  
- Workaround: Keep permitSetMultiParamEntries disabled (default) and avoid passing untrusted objects as parameters.  
- Tradeoff: Disabling the option may require application changes if it was being used for legitimate multi‑parameter SET statements.

#### MySQL — CVE-2026-107821 (CVSS 8.0 HIGH)
**Summary:** In the same version ranges, insufficient validation of FRM metadata fields (counts, offsets, lengths) allows an attacker who can place a crafted FRM file in the data directory to trigger out‑of‑bounds reads/writes, crash the server, or potentially achieve code execution.  
**Affected Features / Interoperability:** Table definition (.frm) file parsing; affects DDL operations, table opening, and any tool that reads FRM files (e.g., mysqlcheck, mysqldump).  
**Source:**  
- https://github.com/MariaDB/server/commit/3b1c2e58abab5571bec4ff52773ddc75b1738da9  
- https://github.com/MariaDB/server/releases/tag/mariadb-10.11.19  
- https://github.com/MariaDB/server/releases/tag/mariadb-10.6.28  
- https://github.com/MariaDB/server/releases/tag/mariadb-11.4.13  
- https://github.com/MariaDB/server/releases/tag/mariadb-11.8.9  
**Actions:**  
- Fix: Upgrade to the patched MariaDB releases.  
- Workaround: Restrict filesystem access to the data directory so untrusted users cannot write FRM files; monitor for unexpected .frm file creation.  
- Tradeoff: Tightening filesystem permissions may impede legitimate admin tasks that need to create or modify table files.

#### MySQL — CVE-2026-107823 (CVSS 7.2 HIGH)
**Summary:** The view FRM parser fails to safely encode embedded newline characters in usernames. A user with CREATE USER and CREATE VIEW WITH GRANT OPTION can craft a username containing newlines that the parser misinterprets as security metadata, potentially leading to privilege escalation.  
**Affected Features / Interoperability:** Username handling in CREATE VIEW statements; impacts any feature that relies on correct parsing of user‑defined identifiers (e.g., view‑based security models).  
**Source:**  
- https://github.com/MariaDB/server/commit/8a642bc8103aadc6b2087d781ba8e1595616a2c4  
- https://github.com/MariaDB/server/releases/tag/mariadb-10.11.19

- https://github.com/MariaDB/server/releases/tag/mariadb-11.4.13  
- https://github.com/MariaDB/server/releases/tag=mariadb-11.8.9  
**Actions:**  
- Fix: Upgrade to MariaDB 10.6.28, 10.11.19, 11.4.13, 11.8.9, 12.3.3, or 13.0.2.  
- Workaround: Avoid granting CREATE VIEW WITH GRANT OPTION to untrusted users; validate usernames for control characters before account creation.  
- Tradeoff: Restricting the GRANT OPTION may limit legitimate delegation of view‑creation privileges.

#### MySQL — CVE-2026-107816 (CVSS 6.4 MEDIUM)
**Summary:** The qc_info plugin can be confused by queries containing embedded null bytes. Reading INFORMATION_SCHEMA.QERY_CACHE_INFO after such a query is cached may read past the end of a heap buffer, possibly disclosing adjacent memory or crashing the server.  
**Affected Features / Interoperability:** Query cache info plugin; impacts monitoring tools that query INFORMATION_SCHEMA.QERY_CACHE_INFO.  
**Source:**  
- https://github.com/MariaDB/server/commit/0931994096b84ecc9ffc8eb3517c7e09e6e8631e  
- https://github.com/MariaDB/server/releases/tag/mariadb-10.11.19  
- https://github.com/MariaDB/server/releases/tag=mariadb-10.6.28  
- https://github.com/MariaDB/server/releases/tag=mariadb-11.4.13  
- https://github.com/MariaDB/server/releases/tag=mariadb-11.8.9  
**Actions:**  
- Fix: Upgrade to the patched MariaDB versions.  
- Workaround: Disable the qc_info plugin if not needed, or avoid executing queries with embedded null bytes in untrusted contexts.  
- Tradeoff: Disabling the plugin removes visibility into query cache statistics.

#### MySQL — CVE-2026-107822 (CVSS 6.4 MEDIUM)
**Summary:** The ACL cache may generate identical keys for role and localhost usernames when both have an empty IP component, allowing a user with CREATE USER to create a colliding principal and inherit another account’s cached privileges.  
**Affected Features / Interoperability:** Internal ACL caching mechanism; impacts privilege checking for role‑based and host‑based accounts.  
**Source:**  
- https://github.com/MariaDB/server/commit/67ea07dd3400004e4f7ae01bf977f4344bbe064b

#### MySQL — CVE-2026-107819 (CVSS 5.9 MEDIUM)
**Summary:** MariaDB Connector/C versions 3.4.1‑3.4.10 perform TLS hostname verification after checking certificate trust, allowing a man‑in‑the‑middle with a valid certificate for another hostname to downgrade authentication to mysql_clear_password and capture the client password.  
**Affected Features / Interoperability:** TLS authentication switch in the C/C++ connector; impacts any application using libmariadb with Zero‑Configuration SSL.  
**Source:**

- Tradeoff: Disabling the feature may require explicit TLS configuration in client code.

#### MongoDB — CVE-2026-82335 (CVSS 8.1 HIGH)

## Cloud Security

The most urgent item is the critical severity flaw in the openPDC Docker image (CVE-2026-105278, CVSS 9.8) which exposes a hard‑coded administrative credential allowing any network‑reachable attacker to gain full administrative control of the application; this outranks all other findings due to its confirmed high impact and lack of authentication requirement.

### Formal Vulnerabilities

#### Kubernetes — CVE-2026-103413 (CVSS 8.8 HIGH)
**Summary:** Improper input validation in Apache Camel Karavan allows an authenticated user of any role to have Karavan apply arbitrary Kubernetes resources (including privileged pods, hostPath volumes, etc.) to the cluster without restricting resource kinds or namespace.  
**Affected Features / Interoperability:** Karavan plugin’s resource‑apply functionality; successful exploitation can lead to host‑level privileges, privilege escalation, and potential cluster compromise affecting workloads, replication, and any downstream services relying on the cluster.  
**Source:**  
- https://camel.apache.org/security/CVE-2026-103413.html  
- https://github.com/apache/camel-karavan/commit/a773db372eab9f180110ad6129d58004a1bce571  
- http://www.openwall.com/lists/oss-security/2026/10/09/17  
**Actions:**  
- Fix: Upgrade to Apache Camel Karavan 4.22.1 or later.  
- Workaround: Restrict the service account used by Karavan to minimal permissions and disable untrusted project imports until patched.  
- Tradeoff: Limiting service account permissions may break legitimate automation that requires broader cluster access.

#### Kubernetes — CVE-2026-55797 (CVSS 8.8 HIGH)
**Summary:** Command injection in Argo CD’s repo-server when processing an SSH Git repository configured with a malicious proxy URL; shell metacharacters in the proxy host/port are not neutralized, allowing execution of arbitrary commands as the repo-server process.  
**Affected Features / Interoperability:** Argo CD repo-server component handling SSH Git repositories; exploitation can lead to theft of Git, Helm, and OCI credentials and compromise of CI/CD pipelines.  
**Source:**  
- https://github.com/argoproj/argo-cd/commit/1e3ddd0b7250aa23f489956b5fab8c13d0493a9f  
- https://github.com/argoproj/argo-cd/commit/9b27aeb1a4fb15d11a0f01cad65dea1fdfc60205  
- https://github.com/argoproj/argo-cd/pull/15864  
- https://github.com/argoproj/argo-cd/releases/tag/v3.3.15  
- https://github.com/argoproj/argo-cd/releases/tag/v3.4.10  
**Actions:**  
- Fix: Upgrade Argo CD to version 3.3.15, 3.4.10, 3.5.4, or 3.6.0-rc2 (or newer).  
- Workaround: Prevent users from creating or updating repository credentials that use a proxy URL, or enforce strict validation of proxy host/port values.  
- Tradeoff: Blocking proxy URL usage may impede legitimate configurations that rely on proxied Git access.

#### Kubernetes — CVE-2026-106563 (CVSS 5.3 MEDIUM)
**Summary:** In Backstage’s @backstage/plugin-kubernetes-backend, the deprecated Kubernetes services endpoint insufficiently validates entity data, letting an authenticated user with Kubernetes read permissions retrieve metadata for workloads outside their intended scope.  
**Affected Features / Interoperability:** Deprecated Kubernetes services endpoint in the Backstage plugin; impact is limited to read‑only disclosure of Kubernetes object metadata across configured clusters, which could aid further attacks.  
**Source:**  
- https://github.com/backstage/backstage/commit/2d5d3e77d630455d6d48cfa8f31fd3c126fd6f29  
- https://github.com/backstage/backstage/releases/tag/v1.54.1  
- https://github.com/backstage/backstage/security/advisories/GHSA-r9ph-3637-55px  
**Actions:**  
- Fix: Upgrade to Backstage 0.21.8 or later.  
- Workaround: Disable the deprecated Kubernetes services endpoint or restrict Kubernetes read permissions to least‑privilege roles.  
- Tradeoff: Disabling the endpoint removes any legacy integration that depends on it.

#### Docker — CVE-2026-105278 (CVSS 9.8 CRITICAL)
**Summary:** The official Docker image for openPDC ships with a fixed administrative credential that is not changed on first use; an attacker with network reach to the management interface can log in with these credentials and obtain full administrative control of the application.  
**Affected Features / Interoperability:** openPDC management interface exposed via the Docker image; compromise can lead to complete control of the openPDC service, data manipulation, and potential pivot to other infrastructure.  
**Source:**  
- https://github.com/cisagov/CSAF/blob/develop/csaf_files/OT/white/2026/icsa-26-281-02.json  
- https://www.cisa.gov/news-events/ics-advisories/icsa-26-281-02  
**Actions:**  
- Fix: No patched version specified in the source; monitor the vendor advisory for an updated image that removes or forces change of the default credential.  
- Workaround: Immediately change the default administrative password, restrict network access to the management interface (e.g., firewall rules, VPN), and disable the default account if possible.  
- Tradeoff: Changing credentials may break existing automation or scripts that rely on the default login until they are updated.

#### Docker — CVE-2026-106581 (CVSS UNSCORED)
**Summary:** Docker Desktop for Windows versions prior to 4.92.0 fail to verify the signature of a package supplied to `docker desktop installer.exe install -package`, allowing an attacker who can convince a user to approve a malicious package to execute arbitrary installer actions with LocalSystem privileges.  
**Affected Features / Interoperability:** Docker Desktop Installer.exe package installation functionality; exploitation yields LocalSystem code execution on the host, compromising the underlying system and any containers or services running thereon.  
**Source:**  
- https://docs.docker.com/desktop/release-notes/#4920  
**Actions:**  
- Fix: Upgrade Docker Desktop to version 4.92.0 or later.  
- Workaround: Only install packages from trusted sources and verify package signatures manually before installation.  
- Tradeoff: Manual signature verification adds operational overhead but does not degrade functionality.
