# Security Digest — 2026-08-29

## Database

The single most urgent item across the Database scope is **CVE-2019-1068** (Microsoft SQL Server), a CISA KEV-confirmed remote code execution vulnerability with a hard remediation due date of **2026-08-29** — three days away. A KEV-confirmed entry always outranks a merely high-CVSS finding because it represents confirmed active exploitation rather than theoretical severity. This demands immediate patching or mitigation of all internet-exposed SQL Server instances ahead of the BOD 26-04 deadline. Beyond that, MongoDB's BI Connector ODBC Driver holds the highest CVSS in the dataset (9.8 CRITICAL, CVE-2026-19001), and a cluster of MariaDB Connector flaws (CVE-2026-55215, CVE-2026-55854–55860) exposes cleartext credential leakage over unencrypted transports — directly relevant to the homelab mTLS/PKI posture.

### Formal Vulnerabilities

**Summary:** Microsoft SQL Server contains a remote code execution vulnerability that could allow an attacker to execute code in the context of the SQL Server Database Engine service account. Downstream impact depends on the service account's permissions (database access, file system, network). The raw data does not specify which SQL Server versions or editions are affected.

**Source:**

**Actions:**

- Workaround: Evaluate internet exposure of each SQL Server asset; restrict network access; ensure compliance with CISA BOD 26-04. If mitigations are unavailable, discontinue use of the product.
- Tradeoff: Discontinuing use of the product may break dependent applications and services relying on SQL Server.

#### [MySQL] — CVE-2026-59335 (CVSS 8.7 HIGH)
**Summary:** Improper case-sensitivity handling (CWE-178) in Cloud Foundry UAA's Identity Zone Endpoint allows a remote authenticated attacker with only `zones.write` authority to bypass the restriction that this authority does not grant access to the privileged `uaa` (system) identity zone. By referencing the zone identifier in a non-lowercase form (e.g., `UAA`), the attacker exploits a mismatch between the case-sensitive authorization layer and the case-insensitive MySQL default collation, overwriting the system zone's JWT signing key and forging admin tokens. This issue only affects UAA deployments backed by MySQL using its default collation; PostgreSQL and HSQLDB backends are not affected.

**Affected Features / Interoperability:** Cloud Foundry UAA identity zone authorization when backed by MySQL with default collation. Impacts JWT signing key management, zone isolation, and any Cloud Foundry deployment that trusts UAA. Replication and client drivers are not directly impacted; the compromise is at the authorization/persistence layer.

**Source:**
- https://www.cloudfoundry.org/blog/cve-2026-59335-uaa-case-insensitive-check-bypass/

**Actions:**
- Fix: Specific patched version not stated in source data; consult Cloud Foundry UAA release notes.
- Workaround: If using MySQL-backed UAA, ensure the collation is not the default case-insensitive one, or restrict `zones.write` authority tightly. No explicit workaround provided in source data.
- Tradeoff: Changing collation or restricting authorities may affect existing zone configurations and application integrations relying on default behavior.

#### [MySQL] — CVE-2026-55215 (CVSS 7.5 HIGH)
**Summary:** MariaDB Connector/Node.js prior to versions 3.3.3, 3.4.6, and 3.5.3 sends credentials before completing certificate fingerprint validation when SSL is enabled without a pinned CA or server certificate. A server selecting `mysql_clear_password` as the initial authentication plugin can receive the password before the post-TLS identity check completes. An active man-in-the-middle can present a self-signed certificate, capture the database password, and authenticate directly even though the connector later rejects the server.

**Affected Features / Interoperability:** MariaDB Connector/Node.js TLS handshake and authentication flow. Impacts any Node.js application connecting to MariaDB/MySQL using `mysql_clear_password` auth over SSL without pinned certificates. Client drivers and connection pools that rely on this connector are affected; replication and extension compatibility are not directly addressed in the raw data.

**Source:**

**Actions:**

- Workaround: Pin a CA certificate or server certificate fingerprint; disable `mysql_clear_password` in favor of a more secure authentication plugin; enforce `sslMode=VERIFY_IDENTITY` or equivalent.
- Tradeoff: Pinning certificates increases operational overhead for certificate rotation. Disabling `mysql_clear_password` may require application and server-side authentication plugin changes.

#### [MySQL] — CVE-2026-55855 (CVSS 6.5 MEDIUM)
**Summary:** MariaDB Connector/Node.js prior to versions 3.2.4, 3.3.3, 3.4.6, and 3.5.3 permits SQL injection when attacker-controlled Buffer parameters are escaped client-side under the big5, gbk, sjis, cp932, or gb18030 client character sets. **Affected Features / Interoperability:** MariaDB Connector/Node.js client-side escaping for multibyte character sets (big5, gbk, sjis, cp932, gb18030). Impacts applications using these charsets with Buffer parameters. Default `utf8mb4` and prepared statements are not affected. #### [MySQL] — CVE-2026-55858 (CVSS 5.9 MEDIUM)
**Summary:** MariaDB Connector/J prior to versions 2.7.14, 3.3.5, 3.4.3, and 3.5.9 encodes and decodes protocol text and performs client-side escaping under the assumption that the connection character set is UTF-8. A server can announce a mid-session change to `character_set_client` through OK-packet session-state tracking (including via `SET NAMES`, stored routines, triggers, server configuration, or a hostile server). If `character_set_client` changes to a non-UTF-8 value, the driver continues to read and write UTF-8 while the server interprets the same bytes under another encoding, causing silent data corruption and a charset-confusion mismatch that can defeat byte-wise quoting or escaping. The fix accepts only `utf8`, `utf8mb3`, or `utf8mb4` after initialization; any other value causes `SQLException` with SQLState `08000` and closes the connection.

**Affected Features / Interoperability:** MariaDB Connector/J character set handling and session-state tracking. Impacts applications where the server can change `character_set_client` mid-session. Silent data corruption and potential escaping bypass. Replication and extension compatibility are not directly addressed in the raw data.

**Source:**
- https://github.com/mariadb-corporation/mariadb-connector-j/commit/300716bef1e1d0370a41be7863b88aa2d55fbb69
- https://github.com/mariadb-corporation/mariadb-connector-j/commit/7b3c69221b5463ee03472654040b3f6b9e5329c7
- https://github.com/mariadb-corporation/mariadb-connector-j/commit/8cfd9df697372ad4ed09fe87a34b34babb6d43d6
- https://github.com/mariadb-corporation/mariadb-connector-j/commit/c555c9b477521be0c35c3a5461f9f46681553607
- https://github.com/mariadb-corporation/mariadb-connector-j/releases/tag/2.7.14

**Actions:**
- Fix: Upgrade to MariaDB Connector/J version 2.7.14, 3.3.5, 3.4.3, or 3.5.9 (depending on branch).
- Workaround: Prevent servers from changing `character_set_client` to non-UTF-8 values (e.g., restrict `SET NAMES` usage, configure server-side defaults). Monitor for `SQLException` with SQLState `08000` as an indicator.
- Tradeoff: Restricting `SET NAMES` may break applications or stored routines that depend on non-UTF-8 character sets. The fix's strict rejection of non-UTF-8 values after initialization may cause connection failures for legacy setups.

#### [MySQL] — CVE-2026-55860 (CVSS 5.9 MEDIUM)
**Summary:** MariaDB Connector/R2DBC prior to version 1.4.1 does not gate clear-text password authentication plugins (`mysql_clear_password` and `dialog`/PAM) on transport encryption because the `AuthenticationPlugin` interface has no capability for a plugin to require a secure connection. A hostile or MITM MariaDB server can send an `AuthSwitchRequest` naming `mysql_clear_password` or `dialog` over a plain-TCP unencrypted connection, and `AuthenticationFlow` permits `ClearPasswordPluginFlow` or `PamPluginFlow` to return the user's password as cleartext bytes on the wire. The disclosed credentials can subsequently be used to authenticate directly to the database server.

**Affected Features / Interoperability:** MariaDB Connector/R2DBC clear-text authentication plugin gating. Impacts any R2DBC-based application connecting over unencrypted transports. Credential leakage enables direct database authentication. Replication and extension compatibility are not directly addressed in the raw data.
