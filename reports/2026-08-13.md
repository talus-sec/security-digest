# Security Digest — 2026-08-13

User Safety: safe

## Cloud Security

The most urgent item is CVE-2026-50516 in Microsoft Azure Kubernetes Service, a critical-severity flaw (CVSS 9.4) that allows an unauthenticated remote attacker to elevate privileges over a network. While no CISA KEV confirmation is present in the provided data, its combination of critical CVSS score, network reachability, and lack of authentication requirement makes it the top priority for immediate remediation.

### Formal Vulnerabilities

#### Microsoft Azure — CVE-2026-50516 (CVSS 9.4 CRITICAL)
**Summary:** A missing authentication vulnerability in Microsoft Azure Kubernetes Service allows an unauthenticated remote attacker to elevate privileges over a network. No special configuration or prior access is required to exploit this flaw.

**Affected Features / Interoperability:** The vulnerability impacts the core authentication mechanism of Azure Kubernetes Service (AKS), potentially affecting cluster management APIs, node communication, and any integrated services relying on AKS for orchestration. Downstream impacts may include unauthorized access to cluster resources, workload manipulation, and compromise of tenant isolation.

**Source:**
- https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-50516

**Actions:**
- Fix: Apply the latest security update from Microsoft as detailed in the advisory.
- Workaround: Restrict network access to AKS management endpoints using firewall rules or private clusters until patched.
- Tradeoff: Network restrictions may temporarily limit administrative access or automation workflows dependent on public AKS endpoints.

#### Microsoft Azure — CVE-2026-68870 (CVSS 5.3 MEDIUM)
**Summary:** In Apache Airflow's Microsoft Azure Key Vault secrets backend, a team-scoped lookup failure falls back to a team-agnostic lookup, allowing a caller in one team to retrieve secrets belonging to another team in multi-team deployments. Exploitation requires only standard user access within a misconfigured environment.

**Affected Features / Interoperability:** Impacts the Azure Key Vault integration in Apache Airflow when operating in multi-team mode. Could lead to cross-tenant secret leakage, credential exposure, and unauthorized access to downstream Azure services relying on those secrets.

**Source:**
- https://github.com/apache/airflow/pull/70876
- https://github.com/apache/airflow/pull/70899
- https://lists.apache.org/thread/dtkk6vtfoj1y4zjyd6s3mzg0v5g9yg0p
- http://www.openwall.com/lists/oss-security/2026/08/10/4

**Actions:**
- Fix: Upgrade to apache-airflow-providers-microsoft-azure version 14.1.0 or later.
- Workaround: Disable multi-team mode or avoid using team-scoped identifiers that could collide with other teams' namespaces.
- Tradeoff: Disabling multi-team mode reduces operational flexibility and may disrupt existing workflows.

#### Microsoft Azure — CVE-2026-73298 (CVSS UNSCORED)
**Summary:** An authenticated Insecure Direct Object Reference (IDOR) vulnerability in the Microsoft Container Migration Solution Accelerator allows users to read, write, and delete processes and files belonging to other authenticated users within the same organization. Exploitation requires valid Entra ID credentials but no elevated privileges.

**Affected Features / Interoperability:** Affects the process and file management APIs of the Container Migration Solution Accelerator. Could result in unauthorized data access, tampering with migration jobs, and potential lateral movement within the organization’s Azure environment.

**Source:**
- https://github.com/microsoft/Container-Migration-Solution-Accelerator/security/advisories/GHSA-27mc-pccp-3x2x

**Actions:**
- Fix: Update to a patched version of the Container Migration Solution Accelerator once available.
- Workaround: Restrict user access to the application and monitor for suspicious activity on affected APIs.
- Tradeoff: Limiting user access may slow down migration operations and reduce usability.

#### Kubernetes — CVE-2026-73263 (CVSS 9.9 CRITICAL)
**Summary:** In Prowler versions prior to 5.36.0, the Kubernetes provider connection test accepts a kubeconfig containing a legacy GCP auth-provider with attacker-controlled `config.cmd-path` and `config.cmd-args`. This leads to arbitrary command execution on the shared worker via `subprocess.Popen`.

**Affected Features / Interoperability:** Impacts the Kubernetes provider connection testing functionality in Prowler. Could allow attackers to execute arbitrary commands on the Prowler worker, potentially compromising the host system and any connected Kubernetes clusters.

**Source:**
- https://github.com/prowler-cloud/prowler/commit/0b782fcb8c24ece7bd38deede2b8f13d8583e39c
- https://github.com/prowler-cloud/prowler/pull/12091
- https://github.com/prowler-cloud/prowler/releases/tag/5.36.0
- https://github.com/prowler-cloud/prowler/security/advisories/GHSA-ccqh-6cjc-wp4j

**Actions:**
- Fix: Upgrade to Prowler version 5.36.0 or later.
- Workaround: Avoid accepting kubeconfig inputs from untrusted sources and validate all kubeconfig content before processing.
- Tradeoff: Restricting kubeconfig input may reduce automation capabilities and increase manual overhead.

#### Kubernetes — CVE-2026-10090 (CVSS 9.0 CRITICAL)
**Summary:** A privilege escalation flaw in Red Hat Advanced Cluster Management (ACM) allows a user with namespace-scoped "edit" privileges to deploy a Helm chart containing cluster-scoped resources, such as a ClusterRoleBinding granting cluster-admin rights, bypassing intended RBAC restrictions.

**Affected Features / Interoperability:** Affects the Application Subscription controller in Red Hat ACM. Could lead to full cluster compromise, unauthorized access to cluster resources, and violation of namespace-level isolation policies.

**Source:**
- https://access.redhat.com/security/cve/CVE-2026-10090
- https://bugzilla.redhat.com/show_bug.cgi?id=2483292

**Actions:**
- Fix: Apply the latest Red Hat ACM security advisory updates.
- Workaround: Revoke "edit" permissions from untrusted users and enforce stricter RBAC policies.
- Tradeoff: Tightening RBAC may impact developer productivity and application deployment workflows.

#### Kubernetes — CVE-2026-18951 (CVSS 8.8 HIGH)
**Summary:** The Red Hat OpenShift AI (RHOAI) overlay for the training operator incorrectly grants `trainjobs` management permissions to the native Kubernetes `edit` ClusterRole, allowing any user with `edit` permissions to create, modify, or delete TrainJobs. Combined with another vulnerability, this can lead to privilege escalation and arbitrary code execution.

**Affected Features / Interoperability:** Impacts the RHOAI training operator and associated machine learning workflows. Could allow unauthorized model training job manipulation, data exfiltration, and potential cluster compromise.

**Source:**
- https://access.redhat.com/errata/RHSA-2026:53262
- https://access.redhat.com/errata/RHSA-2026:53263
- https://access.redhat.com/security/cve/CVE-2026-18951
- https://bugzilla.redhat.com/show_bug.cgi?id=2511187

**Actions:**
- Fix: Apply the latest RHOAI security patches.
- Workaround: Audit and restrict `edit` ClusterRole assignments and monitor for unauthorized TrainJob activity.
- Tradeoff: Restricting ClusterRole usage may affect legitimate ML development workflows.

#### Kubernetes — CVE-2026-4740 (CVSS 8.2 HIGH)
**Summary:** Improper validation of Kubernetes client certificate renewal in Open Cluster Management (OCM) allows a managed cluster administrator to forge a client certificate that can be approved by the OCM controller, enabling cross-cluster privilege escalation.

**Affected Features / Interoperability:** Affects OCM-managed clusters and the hub cluster. Could allow an attacker to gain control over multiple managed clusters and the central hub, undermining the entire fleet management architecture.

**Source:**
- https://access.redhat.com/errata/RHSA-2026:11414
- https://access.redhat.com/errata/RHSA-2026:13542
- https://access.redhat.com/errata/RHSA-2026:13853
- https://access.redhat.com/errata/RHSA-2026:8218
- https://access.redhat.com/errata/RHSA-2026:9848

**Actions:**
- Fix: Apply the latest OCM and ACM security updates.
- Workaround: Implement stricter certificate approval policies and audit certificate issuance logs.
- Tradeoff: Enhanced certificate validation may introduce latency in cluster registration and management operations.

#### Kubernetes — CVE-2026-18381 (CVSS 7.6 HIGH)
**Summary:** The koku-metrics-operator for Red Hat OpenShift allows a user who can edit the CostManagementMetricsConfig custom resource to specify an arbitrary upload URL. The operator then sends its own service-account bearer token to this URL, enabling token theft.

**Affected Features / Interoperability:** Impacts cost management and metrics collection in OpenShift. Could lead to unauthorized access to cluster metrics, billing data, and potential lateral movement using stolen tokens.

**Source:**
- https://access.redhat.com/security/cve/CVE-2026-18381
- https://bugzilla.redhat.com/show_bug.cgi?id=2509251

**Actions:**
- Fix: Apply the latest koku-metrics-operator security patch.
- Workaround: Restrict edit access to CostManagementMetricsConfig resources and monitor for unusual upload destinations.
- Tradeoff: Limiting access may hinder operational visibility into cost metrics.
