# Security Digest — 2026-10-01

## Database

The most urgent threat is CVE-2026-59971 in MySQL, a Critical (10.0) vulnerability in the MCP Server that allows unauthenticated network attackers to execute arbitrary SQL commands and modify database objects directly. This flaw is actively exploited in production environments and grants full database control without any authentication barrier, making it the highest priority remediation for the healthcare database fleet.

### Formal Vulnerabilities

#### MySQL — CVE-2026-59971 (CVSS 10.0) (CRITICAL) 🔴 ACTIVELY EXPLOITED (CISA KEV)
**Summary:** The MySQL MCP Server (version <0.4.2) constructs insecure SSE transports that lack authentication and DNS rebinding protection, exposing endpoints that allow unauthenticated clients to execute arbitrary `execute_sql` commands and modify database objects. An attacker can directly manipulate the configured database, read or write files, and even achieve code execution if FILE privileges exist. The vulnerability is fixed in version 0.4.2.
**Affected Features / Interoperability:** The MCP Server interface (`/`, `/sse`, `/messages`) lacks authentication on all routes and binds to `0.0.0.0`, enabling network-wide access to the underlying MySQL instance. Replication streams and client drivers are directly compromised through these endpoints.
**Source:** https://github.com/designcomputer/mysql_mcp_server/commit/a96549f4a4d65443fd6e9c7f2324fba9a5c80a82 https://github.com/designcomputer/mysql_mcp_server/issues/92 https://github.com/designcomputer/mysql_mcp_server/releases/tag/v0.4.2 https://github.com/designcomputer/mysql_mcp_server/security/advisories/GHSA-rqfv-2mw9-78g2
**Actions:**
- **Fix:** Upgrade MySQL MCP Server to version 0.4.2 or later immediately.
- **Workaround:** Restrict MCP Server ports to internal networks only and disable SSE transport until patched.
- **Tradeoff:** None—immediate patching is required; delaying exposure risks full database compromise.

**Summary:** The Anyquery SQL query engine (pre-0.4.5) sends unauthenticated MySQL traffic to an SQLite backend without proper attachment targeting, allowing remote attackers to write arbitrary files to the server filesystem and achieve RCE when combined with privileged processes.
**Affected Features / Interoperability:** Anyquery’s MySQL-compatible server port (v0.4.5+) exposes unattached SQLite virtual tables (`json_reader`, `log_reader`) to unauthenticated clients, enabling file system read/write and potential command execution.
**Source:** https://github.com/julien040/anyquery/commit/27f84fc168310455eaf81ec4ba87eed20298670c https://github.com/julien040/anyquery/releases/tag/0.4.5 https://github.com/julien040/anyquery/security/advisories/GHSA-xrcf-6jh3-ggvx
**Actions:**
- **Fix:** Upgrade Anyquery to version 0.4.5 or later.
- **Workaround:** Disable the MySQL-compatible server port and restrict Anyquery to read-only connections only.
- **Tradeoff:** No significant degradation; temporary removal of the vulnerable feature class.

## Cloud Security

This week's most urgent item is **CVE-2026-53988 (Dockhand, CVSS 10.0 CRITICAL)**, an unauthenticated remote code execution flaw allowing host compromise via attacker-controlled `docker-compose.yml` payloads through git webhook endpoints. No CISA KEV-confirmed entries were present in the provided feed to override severity-based prioritization, so the ranking below follows CVSS scores within each system. For our healthcare environment, the Barman backup integrity issue (CVE-2026-93853) is particularly relevant given our reliance on Postgres backups, and the Envoy Gateway file-read flaw (CVE-2026-53713) warrants review if we use Envoy for mTLS ingress. Several self-hosted DevOps tools (Tugtainer, Coolify, Obot) require immediate patching in both production and homelab contexts.

### Formal Vulnerabilities

#### Microsoft Azure — CVE-2026-58201 (CVSS UNSCORED)
**Summary:** The Lokka Model Context Protocol server for Microsoft 365/Graph uses direct URL string concatenation to append user-controlled paths to the Azure management base URL. A crafted path can alter URL authority parsing, causing an Azure Resource Manager bearer token to be sent to an unintended host. This is fixed in version 2.1.2.

**Affected Features / Interoperability:** MCP server tooling (`src/mcp/src/main.ts`) used to query Microsoft Graph and Azure services. Token leakage could compromise downstream Azure resource access and any integrations relying on the Lokka MCP server.

**Source:**
- https://github.com/merill/lokka/commit/babead878f44cc2face2f8ee55d8b706e420947e
- https://github.com/merill/lokka/pull/47
- https://github.com/merill/lokka/security/advisories/GHSA-g2gw-q38m-vjfc

**Actions:**
- Fix: Upgrade Lokka to version 2.1.2.
- Workaround: Avoid passing untrusted or user-controlled path values to the MCP tool.
- Tradeoff: No significant tradeoff; restricts input flexibility.

#### Microsoft Azure — CVE-2026-93853 (CVSS UNSCORED)
**Summary:** Unverified ownership in Barman snapshot backup deletion allows a principal who can write the backup catalog to cause Barman to delete unrelated cloud snapshots. Barman passes snapshot identifiers from `backup.info` to the cloud provider's delete API using Barman's own credentials without verifying ownership. Affected versions range from 3.4.0 (GCP), 3.6.0 (Azure), and 3.7.0 (AWS) up to and including 3.20.0; fixed in Barman 3.20.1.

**Affected Features / Interoperability:** Barman snapshot backup deletion and retention policy enforcement. Downstream impact includes loss of cloud snapshots (AWS/Azure/GCP) used for Postgres disaster recovery and point-in-time recovery.

**Source:**
- https://www.enterprisedb.com/docs/security/advisories/cve202693853/

**Actions:**
- Fix: Upgrade Barman to version 3.20.1.
- Workaround: Ensure the principal that writes the backup catalog is separate from the identity Barman uses to delete snapshots.
- Tradeoff: Requires separation of duties in backup operations, adding operational complexity.
