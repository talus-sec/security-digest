# Security Digest — 2026-09-14

## Database

The most urgent issue is CVE-2026-87016 in Open WebUI (a PostgreSQL-integrated AI platform), where a high-severity OAuth/SCIM wildcard injection vulnerability could allow session hijacking of administrator accounts, though PostgreSQL deployments themselves are unaffected. Additionally, MongoDB faces a denial-of-service risk via query planning integer overflow, and MySQL has an authorization bypass in Froxlor's API that could let customers access unauthorized database servers.

### Formal Vulnerabilities

#### Open WebUI — CVE-2026-87016 (CVSS 8.1 HIGH)
**Summary:** An OAuth subject containing wildcard characters (e.g., `%` or `_`) in Open WebUI's authentication flow could resolve to unintended user identities, including administrators, enabling session hijacking. PostgreSQL deployments are explicitly stated as unaffected. Exploitation requires network access to the Open WebUI service and a malicious OAuth provider.

**Affected Features / Interoperability:** The `get_user_by_oauth_sub` and `get_user_by_scim_external_id` functions in the user model, impacting OAuth and SCIM-based user provisioning integrations. PostgreSQL databases connected to Open WebUI are not directly vulnerable.

**Source:** 
- https://github.com/open-webui/open-webui/commit/73c1f5806aeb6345dad5de8f5aa26d1f3d0bef80
- https://github.com/open-webui/open-webui/releases/tag/v0.11.1
- https://github.com/open-webui/open-webui/security/advisories/GHSA-wpmr-8h3q-fwj7

**Actions:**
- Fix: Upgrade to Open WebUI v0.11.1 or later.
- Workaround: Restrict OAuth provider configurations to avoid special characters in subject identifiers.
- Tradeoff: No significant tradeoff if upgrading; manual OAuth subject sanitization may disrupt some identity provider integrations.

#### MongoDB Server — CVE-2026-82076 (CVSS 6.5 MEDIUM)
**Summary:** An authenticated user with read/write privileges can craft queries that trigger an integer overflow in query planning, causing unbounded memory consumption and server termination. This denial-of-service affects all databases on the compromised node.

**Affected Features / Interoperability:** The query planning component of MongoDB Server. Replication and client drivers may fail if the primary node crashes during exploitation.

**Source:** 
- https://jira.mongodb.org/browse/SERVER-128253

**Actions:**
- Fix: Apply MongoDB Server patch (version unspecified in data).
- Workaround: Limit query complexity via application-layer validation or query timeouts.
- Tradeoff: Restrictive query policies may impact legitimate analytical workloads.

#### Froxlor (MySQL) — CVE-2026-90935 (CVSS 4.3 MEDIUM)
**Summary:** Froxlor's `Mysqls.add` API command fails to validate the `mysql_server` parameter against customer allowlists, enabling attackers to provision databases on unauthorized servers. Exploitation requires API access with customer-level credentials.

**Affected Features / Interoperability:** The Froxlor API's MySQL server provisioning functionality. Breaks multi-tenant isolation in hosted database environments.

**Source:** 
- https://github.com/froxlor/froxlor/security/advisories/GHSA-q4rm-m6xh-5pv7
- https://www.vulncheck.com/advisories/froxlor-before-2.3.7-authorization-bypass-via-mysqls-add-api

**Actions:**
- Fix: Upgrade to Froxlor v2.3.7 or later.
- Workaround: Disable the `Mysqls.add` API endpoint or restrict API token permissions.
- Tradeoff: Disabling the API prevents automated MySQL provisioning workflows.

## Cloud Security

Executive Summary: No CISA KEV-confirmed entries are present in today's Cloud Security batch, making CVE-2024-21400 (CVSS 9.0 CRITICAL) affecting Azure Kubernetes Service Confidential Containers the most urgent item due to its critical severity; remaining entries include a high-severity Azure CLI command injection, an OpenTelemetry Operator privilege escalation, and two Docker-related flaws (LangBot WebSocket auth bypass and Apache Storm worker-launcher command injection), all requiring prompt attention.

**Affected Features / Interoperability:** AKS confidential container isolation and tenant workload boundaries; downstream impact on regulated healthcare data separation if clusters are compromised.
**Source:** https://msrc.microsoft.com/update-guide/vulnerability/CVE-2024-21400

#### Kubernetes — CVE-2026-47701 (CVSS 7.7 HIGH)
**Summary:** OpenTelemetry Operator preserves ServiceMonitor bearerTokenFile as HTTPClientConfig.Authorization.CredentialsFile, letting a tenant point it at a Collector pod file (e.g., service-account token) and have the Collector send its contents as bearer auth on scrapes. Requires Collector service-account token or sensitive file mounted and Collector reaching the target.
**Affected Features / Interoperability:** OpenTelemetry Collector scraping, ServiceMonitor CRDs, bearer token propagation, and downstream telemetry integrity.
**Source:** https://github.com/open-telemetry/opentelemetry-operator/security/advisories/GHSA-cxh2-4639-vmc5
**Actions:**
- Fix: Upgrade to OpenTelemetry Operator v0.152.0.
- Workaround: Not specified in provided data.
- Tradeoff: Not specified in provided data.

#### Docker — CVE-2026-90938 (CVSS 8.6 HIGH)
**Summary:** LangBot plugin runtime starts a debug WebSocket server on 0.0.0.0:5401 with plugin_debug_key defaulting to empty string and never set, skipping authentication entirely. Any remote attacker can register arbitrary debug plugins, intercept IM messages, inject replies, send messages as bots, enumerate UUIDs, invoke LLMs, read knowledge bases, and register malicious tools. No patched version was available at publication.
**Affected Features / Interoperability:** LangBot plugin runtime, instant messaging message handling, LLM pipelines, and knowledge-base contents.
**Source:** https://github.com/langbot-app/LangBot/security/advisories/GHSA-m7qm-2mjr-2h4q
**Actions:**
- Fix: No patched version available at time of publication.
- Workaround: Not specified in provided data.
- Tradeoff: Not specified in provided data.

#### Docker — CVE-2026-82430 (CVSS UNSCORED)
**Summary:** Apache Storm worker-launcher changes ownership of the worker directory before reading the command file, allowing a tenant to rewrite contents between the ownership change and read; the parsed command executes as root with host filesystem access, and mount validation is structural only.
**Affected Features / Interoperability:** Docker and OCI worker isolation, host filesystem bind mounts, topology submission, and container privilege boundaries.
**Source:** https://lists.apache.org/thread/8d5pkn486p8vrz5klg6onk5r8k9sd9lv
**Actions:**
- Fix: Upgrade to Apache Storm 3.1.0.
- Workaround: Disable Docker and OCI worker isolation, or restrict topology submission on affected supervisors to trusted principals; launcher must be rebuilt and reinstalled after upgrading.
- Tradeoff: Disabling isolation removes container/host separation; restricting topology submission limits multi-tenant functionality.
