# Security Digest — 2026-09-30

## Database

The most urgent item is **CVE-2026-59971 (CVSS 10.0 CRITICAL)** in the MySQL MCP Server: an unauthenticated, network-reachable flaw that allows arbitrary SQL execution and potential code execution via DNS rebinding when the SSE transport is enabled, affecting any deployment using the Model Context Protocol server with non-default transport settings. No CISA KEV entries appear in this dataset, so the highest-CVSS vulnerability takes precedence. Microsoft SQL Server CVE-2023-54400 (CVSS 9.8) and multiple MongoDB driver flaws (CVSS 8.3) also warrant immediate attention.

### Formal Vulnerabilities

#### MySQL — CVE-2026-59971 (CVSS 10.0 CRITICAL)
**Summary:** The MySQL MCP Server (Model Context Protocol server) prior to version 0.4.2, when configured with `MCP_TRANSPORT=sse`, binds an unauthenticated HTTP/SSE endpoint to `0.0.0.0` without DNS rebinding protection. A remote attacker can directly call the `execute_sql` tool or use DNS rebinding to force a victim's browser to relay same-origin requests, achieving unauthenticated SQL execution. If the MySQL account has `FILE` privileges, this extends to arbitrary file read/write and potential code execution. The default `stdio` transport is not affected.

**Affected Features / Interoperability:** The SSE transport mode of the MySQL MCP Server (`src/mysql_mcp_server/server.py`). Downstream impact includes any AI agent or client using the MCP server to interact with MySQL databases; replication, client drivers, and extensions are not directly affected unless they route through this MCP server.

**Source:** https://github.com/designcomputer/mysql_mcp_server/commit/a96549f4a4d65443fd6e9c7f2324fba9a5c80a82, https://github.com/designcomputer/mysql_mcp_server/issues/92, https://github.com/designcomputer/mysql_mcp_server/releases/tag/v0.4.2, https://github.com/designcomputer/mysql_mcp_server/security/advisories/GHSA-rqfv-2mw9-78g2

**Actions:**
- Fix: Upgrade to MySQL MCP Server 0.4.2 or later.
- Workaround: Do not use `MCP_TRANSPORT=sse`; stick to the default `stdio` transport. If SSE is required, place the service behind an authenticated reverse proxy and restrict network exposure.
- Tradeoff: Disabling SSE transport removes HTTP-based MCP access, which may break integrations expecting HTTP/SSE endpoints. Reverse proxy adds operational complexity.

#### MySQL — CVE-2026-63330 (CVSS 7.7 HIGH)
**Summary:** Warpgate (an SSH/HTTPS/MySQL bastion host) before 0.25.6 fails to enforce admin permission (`RecordingsView`) on the recording stream WebSocket endpoint (`/@warpgate/admin/api/recordings/{uuid}/stream`). **Affected Features / Interoperability:** Warpgate admin API recording stream feature. Downstream: any session recordings captured via Warpgate bastion, including MySQL and PostgreSQL proxied sessions.

**Source:** https://github.com/warp-tech/warpgate/commit/f5cb06ea09065f375870ccee64fe721a2ca79766, https://github.com/warp-tech/warpgate/releases/tag/v0.25.6, https://github.com/warp-tech/warpgate/security/advisories/GHSA-2q37-6vxr-26jr

- Fix: Upgrade Warpgate to 0.25.6 or later.

- Tradeoff: Limiting admin API access may hinder legitimate operational workflows for non-admin users who need recording access.

#### MySQL — CVE-2026-61742 (CVSS UNSCORED)
**Summary:** DBHub (database MCP server for MySQL, Postgres, SQL Server, Oracle, MariaDB, SQLite) prior to 0.22.5 exposes an unauthenticated HTTP MCP endpoint when started with `--transport http`. The Origin/Host hostname equality check does not prevent DNS rebinding, allowing a malicious website to invoke MCP tools from a victim's browser and read/write configured databases.

**Affected Features / Interoperability:** DBHub HTTP transport mode. Downstream: any database connected via DBHub (MySQL, PostgreSQL, SQL Server, Oracle, MariaDB, SQLite); data confidentiality and integrity at risk.

**Actions:**
- Fix: Upgrade DBHub to 0.22.5 or later.
- Workaround: Do not use HTTP transport; use stdio transport or place behind authenticated reverse proxy with DNS rebinding protections.
- Tradeoff: Disabling HTTP transport breaks browser-based or remote MCP client access.

#### MongoDB — CVE-2026-88023 (CVSS 8.3 HIGH)
**Summary:** MongoDB PHP Library GridFS component improperly neutralizes special elements in structured file identifiers, causing them to be interpreted as query conditions. An authenticated user influencing the identifier can read unintended file content or delete all GridFS chunks in a bucket, rendering files unreadable. Rename operations may also target wrong files.

**Affected Features / Interoperability:** MongoDB PHP Library GridFS (`PHPLIB-1929`). Downstream: applications using PHP Library for GridFS file storage; data integrity and confidentiality at risk.

**Source:** https://jira.mongodb.org/browse/PHPLIB-1929

**Actions:**
- Fix: Upgrade MongoDB PHP Library to patched version (check MongoDB release notes for PHPLIB-1929 fix).
- Workaround: Validate and sanitize all caller-supplied GridFS identifiers before passing to library; restrict GridFS access to trusted application code.
- Tradeoff: Input validation adds development effort; may not catch all edge cases.
