# Security Digest — 2026-08-19

User Safety: safe

## Cloud Security

The most urgent issue in cloud security today is **CVE-2026-12564 in Kubernetes**, a CISA KEV-confirmed critical vulnerability (CVSS 9.6) that allows authenticated attackers with credential-creation privileges to exfiltrate Kubernetes service account tokens via the AAP Controller's HashiCorp Vault credential plugin, enabling full control over cluster namespaces and access to sensitive database credentials and Django SECRET_KEY. This vulnerability is actively exploited in the wild and requires immediate patching.

### Formal Vulnerabilities

#### Kubernetes — CVE-2026-12564 (CVSS 9.6 CRITICAL) 🔴 ACTIVELY EXPLOITED (CISA KEV)
**Summary:** The AAP Controller's HashiCorp Vault credential plugin improperly sends Kubernetes service account tokens to attacker-controlled URLs when testing credentials with `kubernetes_role` authentication. An authenticated attacker with credential-creation privileges can exfiltrate tokens and gain full Kubernetes API access.

**Affected Features / Interoperability:** HashiCorp Vault credential plugin, Kubernetes service account token handling, database credential storage, Django SECRET_KEY exposure.

**Source:** [Red Hat Security Advisory](https://access.redhat.com/security/cve/CVE-2026-12564), [Red Hat Bugzilla](https://bugzilla.redhat.com/show_bug.cgi?id=2490556)

**Actions:**
- Fix: Apply Red Hat patches per RHSA-2026:46885, RHSA-2026:47388, RHSA-2026:47735, RHSA-2026:47949, RHSA-2026:47953
- Workaround: Restrict credential-creation privileges; audit Vault credential tests
- Tradeoff: No significant tradeoff if privileges are restricted

#### Kubernetes — CVE-2026-66793 (CVSS 8.8 HIGH)
**Summary:** A flaw in the governance-policy-addon-controller allows users with annotation permissions on ManagedClusterAddOn resources to override container images, enabling cluster-admin privilege escalation and arbitrary code execution on managed clusters.

**Affected Features / Interoperability:** Governance policy addon controller, container image management, cluster-admin role permissions.

**Source:** [Red Hat Security Advisory](https://access.redhat.com/security/cve/CVE-2026-66793), [Red Hat Bugzilla](https://bugzilla.redhat.com/show_bug.cgi?id=2507538)

**Actions:**
- Fix: Apply Red Hat patches per RHSA-2026:11414, RHSA-2026:13542, RHSA-2026:13853, RHSA-2026:8218, RHSA-2026:9848
- Workaround: Restrict annotation permissions on ManagedClusterAddOn resources
- Tradeoff: May limit legitimate governance policy modifications

#### Kubernetes — CVE-2026-17107 (CVSS 8.5 HIGH)
**Summary:** The cluster-proxy service appends caller-supplied impersonation group headers to proxied requests without sanitization, allowing hub principals to escalate to cluster-admin on all managed clusters.

**Affected Features / Interoperability:** Cluster proxy service, impersonation headers, hub-to-spoke cluster communication.

**Source:** [Red Hat Errata RHSA-2026:46885](https://access.redhat.com/errata/RHSA-2026:46885), [RHSA-2026:47388](https://access.redhat.com/errata/RHSA-2026:47388), [RHSA-2026:47735](https://access.redhat.com/errata/RHSA-2026:47735), [RHSA-2026:47949](https://access.redhat.com/errata/RHSA-2026:47949), [RHSA-2026:47953](https://access.redhat.com/errata/RHSA-2026:47953)

**Actions:**
- Fix: Apply Red Hat patches per RHSA-2026:46885, RHSA-2026:47388, RHSA-2026:47735, RHSA-2026:47949, RHSA-2026:47953
- Workaround: Audit and restrict hub principal impersonation permissions
- Tradeoff: May limit legitimate cross-cluster administrative workflows

#### Kubernetes — CVE-2026-4740 (CVSS 8.2 HIGH)
**Summary:** Improper validation of Kubernetes client certificate renewal in Open Cluster Management allows managed cluster administrators to forge certificates, enabling cross-cluster privilege escalation to hub cluster control.

**Affected Features / Interoperability:** Open Cluster Management (OCM), Kubernetes client certificate renewal, hub-spoke cluster trust model.

**Source:** [Red Hat Errata RHSA-2026:11414](https://access.redhat.com/errata/RHSA-2026:11414), [RHSA-2026:13542](https://access.redhat.com/errata/RHSA-2026:13542), [RHSA-2026:13853](https://access.redhat.com/errata/RHSA-2026:13853), [RHSA-2026:8218](https://access.redhat.com/errata/RHSA-2026:8218), [RHSA-2026:9848](https://access.redhat.com/errata/RHSA-2026:9848)

**Actions:**
- Fix: Apply Red Hat patches per RHSA-2026:11414, RHSA-2026:13542, RHSA-2026:13853, RHSA-2026:8218, RHSA-2026:9848
- Workaround: Monitor certificate renewal requests; restrict managed cluster admin privileges
- Tradeoff: May complicate legitimate certificate management workflows

**Affected Features / Interoperability:** Submariner IPsec configuration, cross-cluster network encryption, traffic confidentiality.

**Source:** [Red Hat Security Advisory](https://access.redhat.com/security/cve/CVE-2026-66781), [Red Hat Bugzilla](https://bugzilla.redhat.com/show_bug.cgi?id=2507526)

- Tradeoff: May complicate automated PSK management

#### Docker — CVE-2026-54552 (CVSS 7.9 HIGH)
**Summary:** The `sh` Python library performs incomplete privilege drops when using the `_uid` option, allowing child processes to retain supplementary group access (e.g., docker, root) even after UID change.

**Affected Features / Interoperability:** Python process launching, privilege management, group access control.

**Source:** [GitHub Commit](https://github.com/amoffat/sh/commit/3d855daba91f87a089b490c0d1cf1df3faace2f1), [GitHub Pull Request](https://github.com/amoffat/sh/pull/776), [GitHub Release](https://github.com/amoffat/sh/releases/tag/2.2.4), [GitHub Security Advisory](https://github.com/amoffat/sh/security/advisories/GHSA-q38v-wp89-2w55)

**Actions:**
- Fix: Upgrade to `sh` version 2.2.4
- Workaround: Avoid using `_uid` option; audit group memberships
- Tradeoff: No significant tradeoff with proper upgrade

#### Docker — CVE-2026-46555 (CVSS 7.7 HIGH)
**Summary:** The WhatsApp MCP Server exposes an unauthenticated HTTP API on 127.0.0.1:8080 without Host header validation, allowing local processes (or remote via DNS rebinding) to read arbitrary files and send messages via the WhatsApp bridge.

**Affected Features / Interoperability:** HTTP API, file system access, WhatsApp messaging, DNS rebinding attack surface.

**Source:** [GitHub SECURITY.md](https://github.com/verygoodplugins/whatsapp-mcp/blob/main/SECURITY.md), [GitHub Release](https://github.com/verygoodplugins/whatsapp-mcp/releases/tag/v0.2.1), [GitHub Security Advisory](https://github.com/verygoodplugins/whatsapp-mcp/security/advisories/GHSA-7jj9-4qqq-4xc4)

**Actions:**
- Fix: Upgrade to whatsapp-mcp v0.2.1
- Workaround: Block loopback access to port 8080; run bridge under dedicated user account; avoid untrusted local processes
- Tradeoff: Breaking change for API clients; requires bearer token authentication
