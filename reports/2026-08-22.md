# Security Digest — 2026-08-22

## Database

The most pressing issue is the **Oracle Database CVE‑2026‑71064**, a CRITICAL (CVSS 9.6) vulnerability in the Portable Clusterware component that can be exploited by an unauthenticated attacker with physical network access to the hardware, leading to a full takeover of the cluster. This confirmed high‑severity flaw outranks the other database‑related entries and demands immediate attention.

### Formal Vulnerabilities

#### PostgreSQL — CVE-2026-55769 (CVSS UNSCORED)
**Summary:** A role holding DATABASE OWNER can abuse CloudNativePG’s search_path handling to create overloaded built‑in operators, causing attacker‑controlled functions to run as the PostgreSQL superuser. This enables superuser access, OS command execution via `COPY … FROM PROGRAM`, and exposure of pod ServiceAccount tokens. The issue affects CloudNativePG versions prior to 1.28.4, 1.29.2, and 1.30.0.

**Affected Features / Interoperability:** CloudNativePG’s `fillDefaultParameters`, superuser connection handling, search_path manipulation, instance‑manager introspection queries (`SELECT COUNT(*) > 0 FROM pg_catalog.pg_extension WHERE extname = $1`), the `public.user_search` SECURITY DEFINER function, and direct `sql.Open("pgx", …)` calls. Downstream impact includes any PostgreSQL instance managed by CloudNativePG, client drivers using `sql.Open`, and pod ServiceAccount token leakage.

**Source:** 
- https://github.com/cloudnative-pg/cloudnative-pg/commit/02b5c6289b7609dc87fcb1ae9c113160e3d43308  
- https://github.com/cloudnative-pg/cloudnative-pg/commit/db38f4d80315c8f1b21bf511ef0f28871820c14d  
- https://github.com/cloudnative-pg/cloudnative-pg/commit/e0e2d53adbd907a61f583b1431904b5969f3fd22  
- https://github.com/cloudnative-pg/cloudnative-pg/pull/10774  
- https://github.com/cloudnative-pg/cloudnative-pg/releases/tag/v1.28.4

**Actions:**
- **Fix:** Upgrade CloudNativePG to version 1.28.4, 1.29.2, or 1.30.0.
- **Workaround:** Restrict DATABASE OWNER privileges, pin the `search_path` in configuration, and disable unnecessary superuser connections.
- **Tradeoff:** May break applications that rely on dynamic `search_path` adjustments or require owner‑level privileges for routine tasks.

#### Oracle Database — CVE-2026-71064 (CVSS 9.6 CRITICAL)
**Summary:** An easily exploitable vulnerability in the Portable Clusterware component allows an unauthenticated attacker with access to the physical communication segment attached to the hardware to compromise the clusterware, resulting in a complete takeover of the Portable Clusterware and potentially other products (scope change). No authentication or user interaction is required.

**Affected Features / Interoperability:** The Portable Clusterware component responsible for high‑availability clustering in Oracle Database Server. Because of the scope change, other Oracle products that depend on this clusterware may also be impacted, affecting database services, cluster management, and related applications.

**Source:** https://www.oracle.com/security-alerts/cspuaug2026.html

**Actions:**
- **Fix:** Apply the latest Oracle Critical Patch Update (CPU) for the affected releases (19.3‑19.32, 21.3‑21.23, 23.4.0‑23.26.3).
- **Workaround:** Restrict physical network access to the hardware hosting Portable Clusterware, disable the component if not required, and implement network segmentation.
- **Tradeoff:** May reduce high‑availability capabilities and impact clustering features if the component is disabled.

#### MongoDB — CVE-2026-77070 (CVSS UNSCORED)
**Summary:** A NoSQL injection vulnerability in the n8n MongoDB node’s Find, Delete, and Aggregate operations allows an attacker who can influence the resolved query (e.g., via externally‑controlled data) to inject MongoDB operators such as `$ne` or `$where`. This can turn a single‑document lookup into full‑collection disclosure, deletion, or other destructive operations on the database server.

**Affected Features / Interoperability:** n8n MongoDB node query parsing for Find, Delete, and Aggregate operations. Any MongoDB database accessed through n8n workflows is at risk, potentially affecting downstream data processing and analytics pipelines.

**Source:** 
- https://github.com/n8n-io/n8n/security/advisories/GHSA-953p-jm2c-8h5j  
- https://www.vulncheck.com/advisories/n8n-before-nosql-injection-via-mongodb-node

**Actions:**
- **Fix:** Upgrade n8n to version 1.123.69, 2.33.4, or 2.34.1.
- **Workaround:** Sanitize query inputs, restrict dangerous MongoDB operators, and use a whitelist of allowed operators in workflow configurations.
- **Tradeoff:** May limit legitimate use of advanced MongoDB query features that rely on the previously unrestricted operators.
