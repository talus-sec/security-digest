# Security Digest — 2026-08-18

## Database

The most critical vulnerability requiring immediate attention is CVE-2026-48528, a CISA KEV-confirmed SQL injection flaw in PostgreSQL-based Metacat deployments, which allows unauthenticated attackers to fully compromise protected data. This vulnerability is actively exploited in the wild and demands urgent patching or endpoint disabling.

### Formal Vulnerabilities

#### PostgreSQL — CVE-2026-48528 (CVSS 9.8 CRITICAL) 🔴 ACTIVELY EXPLOITED (CISA KEV)
**Summary:** An unauthenticated SQL injection vulnerability in Metacat's REST API endpoints (`/cn/v1/object` and `/cn/v2/object`) allows attackers to extract, modify, or delete arbitrary data from the underlying PostgreSQL database via the `nodeId` parameter. Exploitation leverages error messages to exfiltrate data, with full proof-of-concept attacks verified.

**Affected Features / Interoperability:** The `/cn` REST API endpoints in Metacat deployments, impacting data catalog management, access logs, and user identifying information in the DataONE network. Disabling these endpoints removes functionality for Coordinating Node deployments.

**Source:** https://github.com/NCEAS/metacat/security/advisories/GHSA-6g6j-wh5h-77h5

**Actions:**
- Fix: Upgrade to Metacat version 3.4.1.
- Workaround: Disable `/cn` REST endpoints by removing servlet mappings in the web.xml file.
- Tradeoff: Loss of API functionality for Coordinating Node deployments.

#### PostgreSQL — CVE-2026-74891 (CVSS 9.8 CRITICAL)
**Summary:** Hardcoded database credentials in `openssl_encrypt` versions before 1.4.0 allow attackers on the same network to access PostgreSQL databases using default credentials, enabling unauthorized data retrieval.

**Affected Features / Interoperability:** PostgreSQL database access via `openssl_encrypt` configurations, potentially exposing all database contents.

**Source:** 
- https://github.com/jahlives/openssl_encrypt/security/advisories/GHSA-v4vm-4xf2-fhqj
- https://www.vulncheck.com/advisories/openssl-encrypt-before-hardcoded-database-credentials

**Actions:**
- Fix: Upgrade to `openssl_encrypt` version 1.4.0 or later.
- Workaround: No interim mitigation specified; immediate patching required.
- Tradeoff: None specified.

#### PostgreSQL — CVE-2026-64657 (CVSS 8.4 HIGH)
**Summary:** Budibase versions before 3.39.19 allow authenticated administrators to execute arbitrary SQL via the PostgreSQL connector due to improper escaping of schema names in `SET search_path` statements.

**Affected Features / Interoperability:** PostgreSQL datasource connector in Budibase, enabling potential data exfiltration or modification through schema configuration fields.

**Source:** 
- https://github.com/Budibase/budibase/commit/67572a82c3850964f388bfd969779dc025a80224
- https://github.com/Budibase/budibase/security/advisories/GHSA-qqf5-x7mj-v43p

**Actions:**
- Fix: Upgrade to Budibase version 3.39.19.
- Workaround: Avoid using double quotes in schema names during configuration.
- Tradeoff: Restricts schema naming conventions.

#### PostgreSQL — CVE-2026-32286 (CVSS 7.5 HIGH)
**Summary:** The `DataRow.Decode` function in pgx fails to validate field lengths, allowing malicious PostgreSQL servers to trigger a panic via negative field lengths in DataRow messages.

**Affected Features / Interoperability:** pgx client library interactions with PostgreSQL servers, potentially causing client-side crashes or denial of service.

**Source:** 
- https://github.com/advisories/GHSA-jqcq-xjh3-6g23
- https://github.com/golang/vulndb/issues/4518
- https://github.com/jackc/pgx/issues/2507
- https://pkg.go.dev/vuln/GO-2026-4518
- https://access.redhat.com/errata/RHSA-2026:11070

**Actions:**
- Fix: Update to the latest pgx version with the fix.
- Workaround: Ensure connections are only made to trusted PostgreSQL servers.
- Tradeoff: None specified.

#### PostgreSQL — CVE-2026-42198 (CVSS 7.5 HIGH)
**Summary:** pgjdbc versions 42.2.0–42.7.10 are vulnerable to client-side denial of service during SCRAM-SHA-256 authentication, as malicious servers can force excessive PBKDF2 iterations, exhausting CPU resources.

**Affected Features / Interoperability:** PostgreSQL JDBC driver connections, potentially disrupting connection pools and application availability.

**Source:** 
- https://github.com/pgjdbc/pgjdbc/releases/tag/REL42.7.11
- https://github.com/pgjdbc/pgjdbc/security/advisories/GHSA-98qh-xjc8-98pq
- https://access.redhat.com/errata/RHSA-2026:19098
- https://access.redhat.com/errata/RHSA-2026:22304
- https://access.redhat.com/errata/RHSA-2026:24348

**Actions:**
- Fix: Upgrade to pgjdbc version 42.7.11.
- Workaround: Set `loginTimeout` to limit connection attempt duration (partial mitigation).
- Tradeoff: Potential connection timeouts during legitimate authentication delays.

#### Oracle Database — CVE-2026-72853 (CVSS 7.6 HIGH)
**Summary:** Budibase versions before 3.40.0 allow SQL injection in the Oracle datasource connector due to improper escaping of table names containing double quotes, enabling authenticated administrators to execute arbitrary SQL.

**Affected Features / Interoperability:** Oracle datasource connector in Budibase, potentially allowing data manipulation or exfiltration through malformed table names.

**Source:**

#### MongoDB — CVE-2026-75852 (CVSS 9.8 CRITICAL)
**Summary:** ArcadeDB versions before 26.8.1 fail to enforce SASL authentication on MongoDB wire-protocol data commands, allowing unauthenticated attackers to execute arbitrary operations on any database via port 27017.

**Affected Features / Interoperability:** MongoDB wire-protocol plugin in ArcadeDB, enabling full database compromise without credentials.

**Source:** 
- https://github.com/ArcadeData/arcadedb/security/advisories/GHSA-fq9c-x968-g278

**Actions:**
- Fix: Upgrade to ArcadeDB version 26.8.1 or later.
- Workaround: Restrict network access to port 27017 to trusted sources only.
- Tradeoff: Reduced accessibility for legitimate remote connections.

## Cloud Security

The most urgent issue in cloud security today is **CVE-2026-42880 in Kubernetes (Argo CD)**, a critical vulnerability (CVSS 9.6) allowing attackers with read-only access to extract plaintext Kubernetes Secrets via the Server-Side Apply dry-run mechanism. This flaw directly impacts cluster security and could lead to credential theft across managed environments. Other notable risks include unpatched vulnerabilities in OpenChoreo and Docker Engine, alongside emerging threats like the Evooo1Bot Linux botnet exploiting edge devices and reported Azure data theft campaigns targeting Fortune 500 companies.

### Formal Vulnerabilities

#### Microsoft Azure — CVE-2026-66802 (CVSS 8.1 HIGH)
**Summary:** A race condition in Azure Attestation and Device Health Attestation Services permits unauthorized network-based code execution. The vulnerability arises from improper synchronization of shared resources during concurrent operations.

**Affected Features / Interoperability:** Azure Attestation service and Device Health Attestation Service. Could disrupt attestation workflows and device compliance checks.

**Source:** [Microsoft Security Update Guide](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-66802)

**Actions:**
- Fix: Apply Microsoft’s August 2026 security updates.
- Workaround: Temporarily disable affected services if feasible.
- Tradeoff: Disabling attestation services may block device compliance validation.

#### Microsoft Azure — CVE-2026-71331 (CVSS 8.1 HIGH)
**Summary:** An integer overflow in Azure Attestation and Device Health Attestation Services enables unauthorized network-based code execution. Attackers can trigger the flaw via malformed inputs to the affected services.

**Affected Features / Interoperability:** Same as CVE-2026-66802.

**Source:** [Microsoft Security Update Guide](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-71331)

**Actions:**
- Fix: Apply Microsoft’s August 2026 security updates.
- Workaround: Same as CVE-2026-66802.
- Tradeoff: Same as CVE-2026-66802.

#### Google Cloud Platform — CVE-2026-15623 (UNSCORED)
**Summary:** A SQL injection flaw in Google SecOps (Chronicle SOAR) versions prior to 6.3.85 allows authenticated attackers to execute blind SQL queries via crafted request parameters. No customer action is required post-patch.

**Affected Features / Interoperability:** Legacy dashboard widget API in Google SecOps. Could compromise data integrity in SOAR workflows.

**Source:** [Google Cloud Release Notes](https://docs.cloud.google.com/chronicle/docs/soar/release-notes#May_23_2026)

**Actions:**
- Fix: Upgrade to version 6.3.85 or later.
- Workaround: None required post-patch.
- Tradeoff: No significant tradeoff.

#### Kubernetes — CVE-2026-42880 (CVSS 9.6 CRITICAL)
**Summary:** Argo CD versions 3.2.0–3.2.10 and 3.3.0–3.3.8 allow attackers with read-only access to extract Kubernetes Secrets via the Server-Side Apply dry-run mechanism. Exploitation requires valid read-only credentials.

**Affected Features / Interoperability:** Argo CD’s ServerSideDiff endpoint. Could expose secrets used in deployments, pipelines, or cluster configurations.

**Source:** [Argo CD Security Advisory](https://github.com/argoproj/argo-cd/security/advisories/GHSA-3v3m-wc6v-x4x3), [Red Hat Errata](https://access.redhat.com/errata/RHBA-2026:12433)

**Actions:**
- Fix: Upgrade to Argo CD 3.2.11 or 3.3.9.
- Workaround: Restrict read-only access to Argo CD; disable Server-Side Apply dry-run if unused.
- Tradeoff: Workarounds may limit legitimate read-only operations.

#### Kubernetes — CVE-2026-73842 (CVSS 9.0 CRITICAL)
**Summary:** OpenChoreo versions prior to 1.0.3, 1.1.3, and 1.2.0-rc.2 expose internal APIs without authentication, enabling network-reachable attackers to read secrets, mutate workloads, and execute commands across data planes.

**Affected Features / Interoperability:** Internal cluster-gateway APIs (`/api/proxy/`, `/api/exec/`, `/api/wirelogs/`). Could lead to full cluster compromise.

**Source:** [OpenChoreo Commit Fixes](https://github.com/openchoreo/openchoreo/commit/50fcae3f1753fd0ac3ae655a3fc080a761c49c04)

**Actions:**
- Fix: Upgrade to OpenChoreo 1.0.3, 1.1.3, or 1.2.0-rc.2.
- Workaround: Restrict network access to internal listeners; enforce mTLS for APIs.
- Tradeoff: Workarounds may complicate legitimate API usage.

#### Kubernetes — CVE-2026-73667 (CVSS 8.8 HIGH)
**Summary:** OpenChoreo Workflow Plane templates prior to 1.0.4, 1.1.4, and 1.2.0-rc.2 allow arbitrary command execution via shell interpolation of user-controlled parameters in workflow pods.

**Affected Features / Interoperability:** Workflow templates under `samples/getting-started/workflow-templates/`. Could enable privilege escalation in pods.

**Source:** [OpenChoreo Commit Fixes](https://github.com/openchoreo/openchoreo/commit/017c3c6d8b27c21d11c8c2b43da1846aa7ae73b9)

**Actions:**
- Fix: Upgrade to OpenChoreo 1.0.4, 1.1.4, or 1.2.0-rc.2.
- Workaround: Audit and sanitize workflow templates; avoid shell interpolation.
- Tradeoff: Workarounds may limit template flexibility.
