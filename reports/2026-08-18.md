# Security Digest — 2026-08-18

## Database

The most urgent issue is CVE-2026-48528 in PostgreSQL, a critical SQL injection vulnerability in Metacat's REST API endpoints that allows unauthenticated attackers to extract, modify, or delete arbitrary data from the database. This vulnerability is confirmed actively exploited by CISA and requires immediate patching or endpoint disabling to prevent full database compromise in healthcare environments handling sensitive patient data.

### Formal Vulnerabilities

#### PostgreSQL — CVE-2026-48528 (CVSS 9.8 CRITICAL) 🔴 ACTIVELY EXPLOITED (CISA KEV)
**Summary:** An unauthenticated SQL injection vulnerability in Metacat's `/cn/v1/object` and `/cn/v2/object` REST API endpoints allows attackers to inject arbitrary SQL commands via the `nodeId` parameter. Exploitation leverages PostgreSQL error messages to exfiltrate data, with full proof-of-concept attacks verified. No authentication is required, and the attack is network-reachable.

**Affected Features / Interoperability:** Impacts Metacat's REST API endpoints used by DataONE Coordinating Nodes. Downstream systems relying on these endpoints for data catalog management, access logs, and user identification (including ORCID identifiers and client IPs) are fully exposed. Disabling the endpoints breaks coordination with member repositories in the DataONE network.

**Source:** [GitHub Security Advisory](https://github.com/NCEAS/metacat/security/advisories/GHSA-6g6j-wh5h-77h5)

**Actions:**
- Fix: Upgrade to Metacat version 3.4.1.
- Workaround: Disable `/cn` REST endpoints by removing servlet mappings for `CNRestServlet` and `CNRestServlet` in Tomcat's `web.xml`.
- Tradeoff: Disables coordination functionality for DataONE member repositories; no alternative if coordination is required.

#### PostgreSQL — CVE-2026-74891 (CVSS 9.8 CRITICAL)
**Summary:** Hardcoded database credentials in `openssl_encrypt` configuration files prior to version 1.4.0 allow attackers on the same network to access PostgreSQL databases using default credentials, enabling retrieval of sensitive data.

**Affected Features / Interoperability:** Affects standalone server configurations using `openssl_encrypt`. Compromised credentials grant full database access, potentially exposing healthcare data.

**Source:** [GitHub Security Advisory](https://github.com/jahlives/openssl_encrypt/security/advisories/GHSA-v4vm-4xf2-fhqj), [VulnCheck Advisory](https://www.vulncheck.com/advisories/openssl-encrypt-before-hardcoded-database-credentials)

**Actions:**
- Fix: Upgrade to version 1.4.0 or later.
- Workaround: Replace hardcoded credentials with environment variables or secure credential management systems.
- Tradeoff: No significant tradeoff if credentials are properly managed.

#### PostgreSQL — CVE-2026-64657 (CVSS 8.4 HIGH)
**Summary:** Budibase's PostgreSQL connector prior to 3.39.19 fails to escape double quotes in schema configuration fields, allowing authenticated administrators to execute arbitrary SQL via the `SET search_path` statement.

**Affected Features / Interoperability:** Impacts Budibase's PostgreSQL datasource connector. Exploitation could compromise database integrity and access control configurations.

**Source:** [GitHub Commit](https://github.com/Budibase/budibase/commit/67572a82c3850964f388bfd969779dc025a80224), [GitHub Security Advisory](https://github.com/Budibase/budibase/security/advisories/GHSA-qqf5-x7mj-v43p)

**Actions:**
- Fix: Upgrade to Budibase 3.39.19 or later.
- Workaround: Restrict administrator access to datasource configurations.
- Tradeoff: Limits administrative flexibility in schema management.

#### PostgreSQL — CVE-2026-32286 (CVSS 7.5 HIGH)
**Summary:** The `DataRow.Decode` function in PostgreSQL drivers fails to validate field lengths, allowing malicious servers to trigger a panic via negative field lengths in DataRow messages.

**Affected Features / Interoperability:** Affects Go-based PostgreSQL clients using the `pgx` driver. Could disrupt application stability and client connections.

**Source:** [GitHub Advisory](https://github.com/advisories/GHSA-jqcq-xjh3-6g23), [Go Vulnerability Database](https://pkg.go.dev/vuln/GO-2026-4518)

**Actions:**
- Fix: Update to patched driver versions (e.g., `pgx` v4.0.1+).
- Workaround: Validate server responses before processing.
- Tradeoff: No significant tradeoff if drivers are updated.

#### PostgreSQL — CVE-2026-42198 (CVSS 7.5 HIGH)
**Summary:** The `pgjdbc` JDBC driver (versions 42.2.0–42.7.10) is vulnerable to client-side DoS during SCRAM-SHA-256 authentication. A malicious server can force excessive PBKDF2 iterations, exhausting client CPU resources.

**Affected Features / Interoperability:** Impacts Java applications using `pgjdbc` for PostgreSQL connections. Could disrupt connection pools and application availability.

**Source:** [pgjdbc Release Notes](https://github.com/pgjdbc/pgjdbc/releases/tag/REL42.7.11), [Red Hat Errata](https://access.redhat.com/errata/RHSA-2026:19098)

**Actions:**
- Fix: Upgrade to `pgjdbc` 42.7.11 or later.
- Workaround: Configure `loginTimeout` and limit concurrent connections.
- Tradeoff: May require connection pool reconfiguration.

#### Oracle Database — CVE-2026-72853 (CVSS 7.6 HIGH)
**Summary:** Budibase's Oracle connector prior to 3.40.0 fails to escape table names with double quotes, enabling SQL injection via write operations on tables containing such identifiers.

**Affected Features / Interoperability:** Affects Budibase's Oracle datasource connector. Could allow unauthorized data access or modification.

**Source:** [GitHub Security Advisory](https://github.com/Budibase/budibase/security/advisories/GHSA-xj29-x47g-9w2c), [VulnCheck Advisory](https://www.vulncheck.com/advisories/budibase-before-sql-injection-via-oracle-connector)

**Actions:**
- Fix: Upgrade to Budibase 3.40.0 or later.
- Workaround: Avoid table names with double quotes.
- Tradeoff: Restricts naming conventions for Oracle tables.

#### MongoDB — CVE-2026-75852 (CVSS 9.8 CRITICAL)
**Summary:** ArcadeDB versions before 26.8.1 fail to enforce SASL authentication on MongoDB wire-protocol commands, allowing unauthenticated attackers to execute insert, find, update, delete, and create operations on any database via port 27017.

**Affected Features / Interoperability:** Impacts ArcadeDB's MongoDB compatibility layer. Full database compromise is possible without credentials.

**Source:** [GitHub Security Advisory](https://github.com/ArcadeData/arcadedb/security/advisories/GHSA-fq9c-x968-g278), [VulnCheck Advisory](https://www.vulncheck.com/advisories/arcadedb-mongodb-wire-protocol-authentication-bypass-cross-database)

**Actions:**
- Fix: Upgrade to ArcadeDB 26.8.1 or later.
- Workaround: Disable MongoDB wire-protocol plugin if unused.
- Tradeoff: Disables MongoDB compatibility features.

#### Redis — CVE-2026-75854 (CVSS 9.8 CRITICAL)
**Summary:** ArcadeDB versions before 26.8.1 have a missing authentication vulnerability in the Redis wire-protocol plugin, allowing unauthenticated attackers to execute arbitrary commands on any database.

**Affected Features / Interoperability:** Affects ArcadeDB's Redis compatibility layer. Enables full data manipulation without credentials.

**Source:** [GitHub Security Advisory](https://github.com/ArcadeData/arcadedb/security/advisories/GHSA-m46c-jh3x-xwrp), [VulnCheck Advisory](https://www.vulncheck.com/advisories/arcadedb-redis-wire-protocol-plugin-missing-authentication)

**Actions:**
- Fix: Upgrade to ArcadeDB 26.8.1 or later.

- Tradeoff: Disables Redis compatibility features.

#### Redis — CVE-2026-35172 (CVSS 7.5 HIGH)
**Summary:** The `distribution` project prior to 3.1.0 allows deleted blobs to be restored via Redis caching misconfiguration, bypassing deletion controls.

**Affected Features / Interoperability:** Affects container image distribution systems using Redis for caching. Could expose deleted container layers.

**Source:** [GitHub Security Advisory](https://github.com/distribution/distribution/security/advisories/GHSA-f2g3-hh2r-cwgc), [Red Hat Errata](https://access.redhat.com/errata/RHSA-2026:23234)

**Actions:**

- Workaround: Disable Redis caching for blob storage.
- Tradeoff: Reduces caching performance for blob operations.

#### Redis — CVE-2026-64865 (CVSS UNSCORED HIGH)
**Summary:** New API versions prior to 1.0.0-rc.16 allow race conditions in Redis-based quota management, enabling authenticated users to retain artificially high billing quotas.

**Affected Features / Interoperability:** Affects New API's user quota tracking. Could lead to unauthorized resource usage.

**Source:** [GitHub Commit](https://github.com/QuantumNous/new-api/commit/dfc0d6324b40c1d6c2972e524409f933541bfb0f), [GitHub Security Advisory](https://github.com/QuantumNous/new-api/security/advisories/GHSA-j6gc-4893-qwmp)
