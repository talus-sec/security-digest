# Security Digest — 2026-08-18

User Safety: safe

## Cloud Security

The most urgent item is CVE-2026-73842 in OpenChoreo, a Kubernetes-native developer platform, which exposes critical internal APIs without authentication, allowing unauthenticated remote attackers to read secrets, mutate workloads, and execute commands across connected clusters. This is compounded by active exploitation reports and a CVSS score of 9.0 (Critical).

### Formal Vulnerabilities

#### Kubernetes — CVE-2026-73842 (CVSS 9.0 CRITICAL) 🔴 ACTIVELY EXPLOITED (CISA KEV)
**Summary:** A race condition in the OpenChoreo Kubernetes platform exposes internal APIs (`/api/proxy/`, `/api/exec/`, `/api/wirelogs/`) without requiring client certificates or tokens, enabling unauthenticated network-reachable attackers to read tenant Kubernetes Secrets, mutate workloads, and execute commands across connected data planes. No authentication is required, and the vulnerability is exploitable over the network.

**Affected Features / Interoperability:** Impacts OpenChoreo versions prior to 1.0.3, 1.1.3, and 1.2.0-rc.2. Affects internal cluster gateway services and any connected data planes relying on OpenChoreo for workload management. Downstream impacts include unauthorized access to Kubernetes Secrets, potential compromise of managed clusters, and lateral movement within Kubernetes environments.

**Source:**  
- https://github.com/openchoreo/openchoreo/commit/50fcae3f1753fd0ac3ae655a3fc080a761c49c04  
- https://github.com/openchoreo/openchoreo/commit/93e6f10953cfc249af2222ddb6730d4b0a729129  
- https://github.com/openchoreo/openchoreo/commit/e3da3c63dcf0895c693cb17ce142ef95e959b62a  
- https://github.com/openchoreo/openchoreo/pull/4256  
- https://github.com/openchoreo/openchoreo/pull/4258  

**Actions:**  
- Fix: Upgrade to OpenChoreo versions 1.0.3, 1.1.3, or 1.2.0-rc.2.  
- Workaround: Restrict network access to internal listeners exposing the vulnerable endpoints.  
- Tradeoff: Network restrictions may limit legitimate internal communication between components.

#### Kubernetes — CVE-2026-73667 (CVSS 8.8 HIGH)
**Summary:** OpenChoreo Workflow Plane templates interpolate developer-controlled parameters into shell commands executed via `sh -c`, allowing authenticated users to inject arbitrary commands into workflow pods. Affected privileged Podman templates also lack `hostUsers: false`, increasing exposure.

**Affected Features / Interoperability:** Impacts OpenChoreo versions prior to 1.0.4, 1.1.4, and 1.2.0-rc.2. Affects workflow execution pipelines and any CI/CD integrations using OpenChoreo templates. Could lead to command injection in workflow pods and potential privilege escalation.

**Source:**  
- https://github.com/openchoreo/openchoreo/commit/017c3c6d8b27c21d11c8c2b43da1846aa7ae73b9  
- https://github.com/openchoreo/openchoreo/commit/65c081ff74618714cb0c82b5d0e0fad2c2cbc46b

**Actions:**  
- Fix: Upgrade to OpenChoreo versions 1.0.4, 1.1.4, or 1.2.0-rc.2.  
- Workaround: Sanitize all developer-supplied parameters before template interpolation.  
- Tradeoff: Parameter sanitization may break legitimate dynamic inputs in workflows.

#### Kubernetes — CVE-2026-17107 (CVSS 8.5 HIGH)
**Summary:** The cluster-proxy service-proxy component in Red Hat Advanced Cluster Management (RHACM) and multicluster-engine (MCE) appends impersonation group headers to proxied requests without removing caller-supplied values. An authenticated hub principal can inject an `Impersonate-Group` header to escalate privileges to cluster-admin on all managed clusters.

**Affected Features / Interoperability:** Impacts RHACM and MCE deployments using the service-proxy component. Affects IAM policy enforcement, cluster management, and cross-cluster operations. Could result in full administrative control over managed clusters.

**Source:**  
- https://access.redhat.com/errata/RHSA-2026:46885  
- https://access.redhat.com/errata/RHSA-2026:47388  
- https://access.redhat.com/errata/RHSA-2026:47735  
- https://access.redhat.com/errata/RHSA-2026:47949  
- https://access.redhat.com/errata/RHSA-2026:47953  

**Actions:**  
- Fix: Apply the latest Red Hat advisory patches for RHACM and MCE.  
- Workaround: Restrict impersonation permissions for the spoke ServiceAccount.  
- Tradeoff: Limiting impersonation permissions may affect legitimate administrative functions.

#### Kubernetes — CVE-2026-4740 (CVSS 8.2 HIGH)
**Summary:** Improper validation of Kubernetes client certificate renewal in Open Cluster Management (OCM) allows a managed cluster administrator to forge a client certificate approved by the OCM controller, enabling cross-cluster privilege escalation and potential control over other managed clusters, including the hub cluster.

**Affected Features / Interoperability:** Impacts OCM-based systems including RHACM. Affects certificate-based authentication, cluster registration, and inter-cluster communication. Could lead to unauthorized access across multiple clusters.

**Source:**  
- https://access.redhat.com/errata/RHSA-2026:11414

- https://access.redhat.com/errata/RHSA-2026:9848  

**Actions:**  
- Fix: Update to patched versions of OCM/RHACM as specified in Red Hat advisories.

- Tradeoff: Stricter validation may complicate legitimate certificate renewal processes.

#### Kubernetes — CVE-2026-9165 (CVSS 7.7 HIGH)
**Summary:** Red Hat Advanced Cluster Security for Kubernetes (RHACS) Central does not limit the depth of GraphQL queries on its authenticated API, allowing authenticated users with valid API tokens to send deeply nested queries that consume excessive resources, causing denial of service for the management plane.

**Affected Features / Interoperability:** Impacts RHACS Central management plane. Affects security monitoring, policy enforcement, and cluster visibility dashboards. Could disrupt security operations and incident response capabilities.

**Source:**  
- https://access.redhat.com/errata/RHSA-2026:36207  
- https://access.redhat.com/errata/RHSA-2026:36319  
- https://access.redhat.com/errata/RHSA-2026:36625  
- https://access.redhat.com/security/cve/CVE-2026-9165  
- https://bugzilla.redhat.com/show_bug.cgi?id=2480505  

**Actions:**  
- Fix: Apply the latest RHACS patches from Red Hat advisories.  
- Workaround: Implement rate limiting and query depth restrictions at the API gateway level.  
- Tradeoff: Rate limiting may impact legitimate API usage during high-traffic periods.

#### Docker — CVE-2025-27770 (CVSS UNSCORED)
**Summary:** The `/create_project` endpoint in UpTrain (version 0.7.1 and prior) is vulnerable to remote code execution via the `checks` and `metadata` parameters. **Affected Features / Interoperability:** Impacts UpTrain versions 0.7.1 and prior. Affects project creation workflows, AI application evaluation pipelines, and Docker-based deployments. Could lead to full container compromise and lateral movement.
